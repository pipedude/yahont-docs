title: "LumApps"
description: "Индексирование содержимого интранета из LumApps"
---

Коннектор LumApps индексирует опубликованное содержимое вашего интранета LumApps: страницы,
новости и любые пользовательские типы содержимого, которые определила ваша организация.

Коннектор входит как приложение и действует от имени **сервисного пользователя**. Он индексирует только то содержимое,
которое может прочитать этот сервисный пользователь, поэтому область коннектора определяет доступ этого пользователя.

## Как это работает {#how-it-works}

| Содержимое | Поведение |
| ----------- | -------------------------------------------------------------------------------------------------------------------------- |
| Содержимое | Один документ на элемент содержимого LumApps. Yahont индексирует его заголовок и текст и сохраняет ссылку на LumApps. |
| Только опубликованное | Индексируется только содержимое, которое LumApps отмечает как опубликованное (live). Архивное и неопубликованное содержимое пропускается. |
| Метаданные | Значения метаданных заменяются их подписями, поэтому тег отображается по названию, а не по внутреннему идентификатору. |
| Язык | Содержимое и подписи метаданных читаются на одном языке. Смотрите параметр **Language** ниже. |
| Права | Недоступны. **Автосинхронизация прав** для LumApps не предлагается, поэтому тип доступа может быть только **Публичный** или **Приватный**. |

Индексация сохраняет контрольные точки, поэтому большой интранет обрабатывается за несколько попыток,
а не за один долгий запуск.

<Warning>
  Тип доступа применяется ко всему, что может прочитать сервисный пользователь.
  Если у этого пользователя широкий доступ к интранету и вы выберете **Публичный**,
  всё это станет видно каждому пользователю Yahont. Дайте сервисному пользователю тот доступ,
  который должен быть у Yahont.
</Warning>

## Перед началом {#before-you-begin}

Вам понадобятся:

- API-хост **ячейки** (cell) LumApps, например `https://go-cell-005.api.lumapps.com`
- Числовой идентификатор организации LumApps
- Приложение LumApps с идентификатором и API-ключом
- Сервисный пользователь, от имени которого действует приложение: адрес электронной почты или идентификатор пользователя
- Аккаунт администратора Yahont

<Note>
  Базовый URL API — это хост ячейки вашей организации, а не сайт документации LumApps `api.lumapps.com`.
  С неверным хостом аутентификация не проходит. Если вы не знаете хост ячейки, спросите его в поддержке LumApps.
</Note>

## Настройка Yahont {#configure-onyx}

<Steps>
  <Step title="Откройте коннектор LumApps">
    В Yahont перейдите в **Панель администратора → Добавить коннектор** и выберите **LumApps**.
  </Step>

  <Step title="Создайте учётные данные">
    Введите идентификатор приложения в поле **LumApps Application ID**, ключ — в **LumApps API Key**,
    а сервисного пользователя — в **LumApps Service User**. Значение с `@` считается адресом электронной почты,
    любое другое — идентификатором пользователя.

    <img className="rounded-image" src="/assets/admins/connectors/lumapps/LumAppsCredential.png" alt="Создание учётных данных LumApps с идентификатором приложения, API-ключом и сервисным пользователем"/>
  </Step>

  <Step title="Введите хост и организацию">
    Задайте название коннектора.
    Введите хост ячейки в поле **API Base URL (cell host)** и числовой идентификатор организации в поле **Organization
    ID**.
  </Step>

  <Step title="Выберите тип доступа">
    **Публичный** делает всё проиндексированное содержимое LumApps видимым для каждого пользователя Yahont.
    **Приватный** ограничивает коннектор выбранными группами пользователей Yahont. Это функция Enterprise Edition:
    группы пользователей в Yahont CE недоступны.
  </Step>

  <Step title="Подключитесь и проверьте">
    Нажмите **Создать коннектор**. Перед сохранением Yahont читает один элемент содержимого,
    чтобы проверить учётные данные. Затем откройте **Панель администратора → Существующие коннекторы**,
    выберите коннектор и убедитесь, что первая попытка индексации завершилась.
  </Step>
</Steps>

### Расширенные настройки {#advanced-settings}

| Параметр | По умолчанию | Назначение |
| ----------------------- | ------- | -------------------------------------------------------------------------------------------------------------------- |
| Instance (site) IDs | пусто | Индексировать только эти инстансы LumApps. Оставьте пустым, чтобы индексировать всё, что может прочитать сервисный пользователь. |
| Custom Content Type IDs | пусто | Индексировать только эти пользовательские типы содержимого. Оставьте пустым, чтобы индексировать все типы содержимого. |
| Language | `en` | Язык заголовков, текста содержимого и подписей метаданных в виде кода ISO 639-1, например `en` или `fr`. |

<Note>
  **Language** выбирает один язык и не индексирует несколько.
  В многоязычном интранете содержимое индексируется на выбранном здесь языке. Чтобы индексировать второй язык,
  добавьте второй коннектор с другим значением **Language**.
</Note>

## Ограничения {#limits}

| Ограничение | Значение | Примечания |
| -------------------- | ----- | ------------------------------------------------------------------------------------------- |
| Вызов API LumApps | 60 с | |
| Повторов на запрос | 5 | Пауза между попытками до 60 с; учитывается заголовок `Retry-After`, если LumApps его отправляет. |
| Элементов на запрос | 100 | Максимум LumApps. Yahont никогда не запрашивает больше. |

Токен доступа живёт недолго, и Yahont получает новый за минуту до истечения старого,
поэтому менять токены с вашей стороны не нужно. Коннектор не скачивает файлы, поэтому ограничения на размер файла нет.

## Устранение неполадок {#troubleshooting}

<AccordionGroup>
  <Accordion title="Учётные данные отклонены">
    `LumApps credentials are invalid or expired` означает,
    что идентификатор приложения или API-ключ неверные либо приложение удалено. Проверьте оба значения,
    а также что **API Base URL (cell host)** и **Organization ID** относятся к одной организации LumApps.
  </Accordion>

  <Accordion title="Сервисный пользователь не может читать содержимое">
    `The LumApps service user lacks permission to read content` означает, что аутентификация прошла,
    но у сервисного пользователя нет доступа. Выдайте ему в LumApps доступ к инстансам, которые нужно индексировать.
  </Accordion>

  <Accordion title="Аутентификация не проходит на хосте документации">
    С `api.lumapps.com` вместо хоста ячейки аутентификация не проходит. Введите хост ячейки вашей организации,
    например `https://go-cell-005.api.lumapps.com`.
  </Accordion>

  <Accordion title="Нет содержимого">
    Индексируется только опубликованное содержимое, поэтому архивные и неопубликованные элементы не появляются.
    Проверьте, что инстанс LumApps указан в **Instance (site) IDs**, если это поле не пустое,
    что его тип указан в **Custom Content Type IDs**, если это поле не пустое,
    и что сервисный пользователь может его открыть.
  </Accordion>

  <Accordion title="Заголовки или теги отображаются не на том языке">
    Задайте в **Language** нужный код ISO 639-1. Один коннектор индексирует один язык;
    для второго языка добавьте второй коннектор.
  </Accordion>
</AccordionGroup>
