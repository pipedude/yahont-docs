## Как это работает {#how-it-works}

Коннектор Jira каждые **10** минут получает все заявки из указанных проектов.

Для каждой задачи Jira этот коннектор получает:

- Заголовок
- Описание
- [Общие поля](#indexed-metadata)
- Комментарии

Коннектор может индексировать только то содержимое, к которому есть доступ у его аккаунта Jira.
API-токен не даёт его владельцу дополнительных прав в Jira.

## Настройка Jira Cloud {#jira-cloud-setup}

Jira Cloud размещается и обновляется Atlassian. URL сайта обычно заканчивается на `atlassian.net`.
Если ваша организация сама управляет развёртыванием и версией Jira,
используйте [настройку Jira Data Center](#jira-data-center-setup).

### 1. Выберите аккаунт коннектора {#1-choose-a-connector-account}

Используйте для коннектора отдельный аккаунт Jira. Так его доступ проще проверять,
а изменение личного аккаунта не остановит коннектор.

Создайте аккаунт или выберите существующий, прежде чем предоставлять доступ или создавать API-токен.

### 2. Узнайте, где проверять и предоставлять доступ {#2-learn-where-to-check-and-grant-access}

Коннектор индексирует только проекты, задачи и комментарии, к которым есть доступ у его аккаунта Jira.
Используйте проверки ниже,
чтобы выяснить причину отсутствия содержимого или предоставить доступ для синхронизации прав на шаге 4.

Попросите администратора Jira выполнить эти шаги, будучи авторизованным в Jira:

<Steps>
  <Step title="Управление глобальными правами">
    Откройте **Settings > System > Global permissions**. На этой странице видно,
    у каких пользователей и групп есть каждое глобальное право. Используйте **Grant permission**,
    чтобы добавить пользователя или группу. Также можно добавить аккаунт коннектора в группу,
    у которой это право уже есть.

    См.
    [инструкции Atlassian по глобальным
    правам](https://support.atlassian.com/jira-cloud-administration/docs/view-grant-revoke-global-permissions-in-jira/).
  </Step>

  <Step title="Управление правами проектов, управляемых компанией">
    Откройте **Settings > System > Admin Helper > Permission Helper**. Введите аккаунт коннектора,
    типичную задачу и право, которое хотите проверить.

    Чтобы выдать недостающее право, обновите схему прав проекта. Предоставьте его аккаунту,
    одной из его групп или одной из его ролей проекта.
    Повторите проверку для каждой используемой схемы прав и каждого уровня безопасности задач.

    См.
    [инструкции Atlassian по Permission
    Helper](https://support.atlassian.com/jira-cloud-administration/docs/check-a-users-access-from-a-work-item/).
  </Step>

  <Step title="Управление доступом к проектам, управляемым командой">
    На боковой панели проекта откройте **Space settings > Access**. Добавьте аккаунт коннектора и назначьте его роль.
    Проверьте уровень доступа проекта и каждую роль, которая может просматривать задачи.

    См. [инструкции Atlassian по доступу к проектам,
    управляемым
    командой](https://support.atlassian.com/jira-software-cloud/docs/manage-how-people-access-your-team-managed-project/).
  </Step>

  <Step title="Проверьте ограниченное содержимое">
    Войдите как аккаунт коннектора. Убедитесь,
    что он может открыть типичные задачи и комментарии из каждого типа ограничений, которое вы хотите индексировать.
  </Step>
</Steps>

### 3. Предоставьте доступ для индексации {#3-grant-indexing-access}

Для индексации без синхронизации прав аккаунту Jira нужны:

- Доступ к продукту Jira.
- **Browse Projects** для каждого проекта, управляемого компанией, который вы хотите индексировать.
- Роль, которая может просматривать задачи в каждом проекте, управляемом командой, который вы хотите индексировать.
- Доступ к каждому уровню безопасности задач, используемому в индексируемых задачах.
- Доступ к каждому ограниченному комментарию, который вы хотите индексировать.

Jira опускает проекты, задачи и комментарии, к которым у аккаунта нет доступа.
Обычный пользователь Jira может запускать коннектор, если у него есть весь необходимый доступ.

### 4. Добавьте доступ для синхронизации прав {#4-add-permission-sync-access}

<Warning>
  Yahont считает всё внутри проекта Jira доступным каждому, кто видит проект.
  Он не синхронизирует уровни безопасности задач Jira и видимость ограниченных комментариев.
  Не включайте синхронизацию прав для проектов, где используются такие ограничения.
</Warning>

Предоставьте весь доступ для индексации из предыдущего шага.
Затем предоставьте один из следующих административных вариантов:

- **Administer Jira** глобально.
- **Administer Projects** в каждом индексируемом проекте, управляемом компанией,
  и роль **Administrator** в каждом индексируемом проекте, управляемом командой.

Если у аккаунта нет **Administer Jira**, также нужно предоставить глобальное право **Browse users and groups**.
Yahont использует этот доступ, чтобы читать схемы прав, роли проектов, пользователей, группы и членство в группах.

<Note>
  **Administer Jira** не всегда даёт доступ к содержимому задач.
  Предоставляйте и проверяйте доступ для индексации отдельно.
</Note>

### 5. Создайте API-токен {#5-create-the-api-token}

Создайте API-токен от имени аккаунта коннектора.
Следуйте [инструкциям Atlassian по
API-токенам](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/).

Если вы создаёте токен с областями, включите **Using scoped token** при настройке коннектора в Yahont.

Для индексации предоставьте токену область `read:jira-work`.
Для синхронизации прав также предоставьте `read:jira-user` и `manage:jira-configuration`.
Либо предоставьте полный набор гранулярных областей чтения, перечисленных для этих API Jira:

- [Поиск и получение задач](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/)
- [Схемы прав проектов](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-project-permission-schemes/)
- [Роли проектов](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-project-roles/)
- [Группы и участники групп](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-groups/)

Области токена ограничивают токен. Они не заменяют доступ аккаунта коннектора из предыдущих шагов.

- Доступ к каждому уровню безопасности задач, используемому в индексируемых задачах.

  Yahont считает всё внутри проекта Jira доступным каждому, кто видит проект.

Предоставьте весь доступ для индексации из предыдущего шага.
Затем добавьте аккаунт коннектора в группу с одним из этих глобальных прав:

- **Jira administrators**
- **Jira System administrators**

### 5. Создайте персональный токен доступа {#5-create-the-personal-access-token}

Создайте персональный токен доступа от имени аккаунта коннектора.
Следуйте [инструкциям Atlassian по токенам Jira Data
Center](https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html).

У токена тот же доступ, что и у его аккаунта Jira.
Персональные токены доступа Jira Data Center не используют области API Jira Cloud.

## Ограничения синхронизации прав {#permission-sync-limitations}

Изучите эти ограничения, прежде чем включать синхронизацию прав:

- Yahont сопоставляет пользователей Jira с пользователями Yahont по адресу электронной почты. Видимость профиля в Jira Cloud может скрывать `emailAddress`
  даже для API-токена администратора.
  Jira Data Center также может скрывать или маскировать адреса электронной почты пользователей. Отсутствующий,
  скрытый или замаскированный адрес не позволяет Yahont сопоставить этого пользователя. См.
  [документацию Atlassian по видимости профиля](https://developer.atlassian.com/cloud/jira/platform/profile-visibility/)
  и [настройки видимости адресов электронной почты в Data
  Center](https://confluence.atlassian.com/adminjiraserver0912/configuring-jira-application-options-1346048127.html).
- Yahont поддерживает статические выдачи **Browse Projects** пользователям, группам и ролям проектов.
  Динамические выдачи, такие как Reporter, Assignee, Project Lead и пользовательские поля пользователей,
  нельзя сопоставить со статическим списком доступа Yahont.
- Yahont считает выдачи Jira **Anyone** и **Application access** доступными всем пользователям Yahont.
  Доступ к приложению Jira обычно включает только лицензированных пользователей Jira.
  Такое сопоставление может дать доступ пользователям Yahont, у которых нет доступа к Jira.
- Синхронизация прав запрашивает до 9999 групп Jira, видимых аккаунту коннектора.
  Jira может применять меньший лимит, поэтому на больших сайтах синхронизироваться могут не все группы.
- Срок действия API-токенов Jira Cloud — от 1 до 365 дней. Меняйте токен до истечения срока.

## Настройка коннектора {#configure-the-connector}

<Steps>
  <Step title="Откройте коннектор Jira">
    Откройте панель администратора и выберите коннектор **Jira**.
  </Step>

  <Step title="Укажите учётные данные">
    Выберите **Create New**. Для Jira Cloud введите адрес электронной почты аккаунта коннектора и API-токен.
    Для Jira Data Center оставьте поле адреса электронной почты пустым и введите персональный токен доступа.

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraCredential.png" alt="Форма учётных данных Jira в Yahont с полями адреса электронной почты и токена"/>

    Нажмите **Create**, выберите учётные данные и нажмите **Continue**.
  </Step>

  <Step title="Настройте источник Jira">
    Введите название коннектора и базовый URL Jira.
    Для Jira Cloud базовый URL обычно `https://your-domain.atlassian.net`. Включите **Using scoped token**,
    если вы создали токен Jira Cloud с областями.
  </Step>

  <Step title="Выберите, что индексировать">
    Выберите один режим индексации:

    - **Everything** индексирует все задачи, к которым есть доступ у аккаунта коннектора.
    - **Project** индексирует один проект Jira. Введите его ключ, например `PROJ`.
    - **JQL Query** индексирует задачи, соответствующие пользовательскому запросу JQL.
    Не включайте временные фильтры и предложение `ORDER BY`.

    Чтобы исключить комментарии от определённых аккаунтов,
    добавьте их адреса электронной почты в **Comment Email Blacklist**.

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraProject.png" alt="Режимы индексации коннектора Jira, ключ проекта и чёрный список адресов электронной почты комментаторов"/>
  </Step>

  <Step title="Выберите доступ к документам">
    Выберите **Public**, **Private** или **Auto Sync Permissions**. Выберите **Auto Sync Permissions**,
    чтобы наследовать доступ к проектам Jira.

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraPermissionSync.png" alt="Коннектор Jira с выбранной автоматической синхронизацией прав"/>
  </Step>

  <Step title="Настройте необязательные расписания">
    Выберите **Advanced**, чтобы изменить частоту очистки, частоту обновления или дату начала индексации.

    <img className="rounded-image" src="/assets/admins/connectors/jira/JiraAdvanced.png" alt="Расписание и дата начала индексации коннектора Jira"/>
  </Step>

  <Step title="Создайте коннектор">
    Нажмите **Create Connector**. Yahont начнёт индексировать задачи Jira, соответствующие вашей конфигурации.
  </Step>
</Steps>

- Assignee
