Используйте это руководство для Confluence Data Center и устаревшего Confluence Server.
Yahont использует один и тот же путь коннектора для обоих.

<Warning>
  Atlassian прекратила поддержку Confluence Server 15 февраля 2024 года.
  По возможности используйте поддерживаемый выпуск Data Center.
</Warning>

## Поддерживаемая аутентификация {#supported-authentication}

Yahont использует персональный токен доступа Confluence (PAT) как bearer-токен.
Confluence Data Center и Server получили PAT в версии 7.9.
Более ранние выпуски не могут использовать текущий путь аутентификации Yahont.

Используйте отдельный аккаунт Confluence. Предоставьте ему право просмотра каждого пространства и ограниченной страницы,
которые вы хотите индексировать. PAT имеет тот же доступ в Confluence, что и его владелец.

## Создание персонального токена доступа {#create-the-personal-access-token}

<Steps>
  <Step title="Откройте персональные токены доступа">
    Войдите как аккаунт коннектора. Нажмите аватар пользователя, выберите **Settings**,
    затем **Personal access tokens**.
  </Step>

  <Step title="Создайте токен">
    Выберите **Create token**. Введите описательное имя и задайте срок действия, если этого требует ваша политика.
  </Step>

  <Step title="Скопируйте токен">
    Выберите **Create**, затем скопируйте токен. Confluence показывает значение один раз.
    Храните его в менеджере секретов, пока не добавите в Yahont.

    См.
    [инструкции по PAT для Data
    Center](https://confluence.atlassian.com/enterprise/using-personal-access-tokens-1026032365.html) от Atlassian.
  </Step>
</Steps>

## Добавьте учётные данные в Yahont {#add-the-credential-to-onyx}

Откройте **Панель администратора > Коннекторы > Confluence**, нажмите **Создать** и введите:

- **Name**: понятное название, например `Confluence Data Center - docs account`.
- **Confluence Username**: имя пользователя владельца PAT в Confluence.
  Клиент Server/Data Center аутентифицируется с помощью PAT,
  но Yahont по-прежнему требует это поле в общей форме учётных данных.
- **Confluence Access Token**: PAT.

![Диалог учётных данных Confluence в Yahont](/assets/admins/connectors/confluence/credential-form.jpg)

## Настройка коннектора {#configure-the-connector}

Выберите учётные данные, нажмите **Продолжить** и настройте следующие поля:

- Отключите **Is Cloud**.
- Задайте **Wiki Base URL** как корень сайта для пользователей, например `https://confluence.example.com`.
- Включите настроенный контекстный путь, например `https://example.com/confluence`.
- Не добавляйте `/rest/api`.
- Оставьте **Using scoped token** выключенным.
- Выберите область индексации и настройку вложений, описанные в [обзоре Confluence](./confluence).

![Коннектор Confluence Data Center с отключённым Is
Cloud](/assets/admins/connectors/confluence/connector-form-data-center.jpg)

## Настройка синхронизации прав {#configure-permission-sync}

Синхронизация прав требует Yahont Enterprise Edition. Yahont читает права на пространства, ограничения страниц,
унаследованные ограничения родительских страниц, пользователей, группы и членство в группах.
Он сопоставляет пользователей Confluence с пользователями Yahont по адресу электронной почты.

### Data Center 9.1 и новее {#data-center-91-and-later}

Yahont использует REST API прав на пространства, появившийся в Data Center 9.1.
Предоставьте аккаунту коннектора одну из ролей:

- Администратор Confluence для сайта.
- Администратор пространства для каждого индексируемого пространства.

Confluence может возвращать HTTP `500` вместо `403`, если у аккаунта нет такого доступа.
Предоставьте нужную роль администратора и повторите проверку коннектора.

Если в вашем выпуске есть глобальное разрешение **Browse All Group Members**,
предоставьте его аккаунту коннектора или одной из его групп. Yahont должен читать состав групп,
чтобы применять доступ к пространствам и страницам на основе групп.

### Data Center или Server 7.9–9.0 {#data-center-or-server-79-through-90}

В этих выпусках нет REST API прав на пространства. Yahont переходит на устаревший API JSON-RPC.
Используйте аккаунт администратора Confluence или сделайте аккаунт коннектора администратором каждого индексируемого
пространства. Для настройки удалённого API на первом шаге нужен системный администратор.

<Warning>
  Более старые развёртывания Confluence могут вести себя иначе, а их API не всегда хорошо документированы.
  Если вам нужна помощь, напишите на [support@yahont.ai](mailto:support@yahont.ai).
</Warning>

<Steps>
  <Step title="Включите удалённый API">
    В Confluence откройте **Administration > General Configuration > Further Configuration**, нажмите **Edit**,
    включите **Remote API (XML-RPC & SOAP)** и сохраните. Для этой настройки нужен доступ системного администратора.

    См. [инструкции по удалённому API](https://confluence.atlassian.com/doc/enables-the-remote-api-150460.html)
    от Atlassian.
  </Step>

  <Step title="Проверьте Secure Administrator Sessions">
    Secure Administrator Sessions, также называемые WebSudo,
    могут перехватывать устаревшие вызовы JSON-RPC в Confluence 7.7 и новее.
    Если синхронизация прав получает HTML-ответ входа вместо JSON,
    по возможности обновитесь до Data Center 9.1 или новее. Если обновиться нельзя,
    попросите администратора безопасности Confluence оценить,
    стоит ли отключить Secure Administrator Sessions в **General Configuration > Security Configuration**.
    Отключение снижает защиту для всех администраторов сайта.
  </Step>
</Steps>

### Проверка сопоставления пользователей и групп {#check-user-and-group-mapping}

- Сделайте адреса электронной почты пользователей видимыми аккаунту коннектора.
- Убедитесь, что адрес электронной почты каждого пользователя Confluence совпадает с адресом пользователя в Yahont.
- Проверьте пользователей из внутренних и внешних каталогов пользователей.
- Проверьте прямые права пользователей, права групп, ограничения страниц и унаследованные ограничения.

Atlassian исправила дефект постраничной выдачи списка пользователей в Data Center 10.1.0, 9.2.8 и 8.5.26.
Более ранние затронутые версии могут возвращать дубликаты пользователей и пропускать других.
Обновитесь до исправленного выпуска, прежде чем полагаться на полную синхронизацию прав на основе групп. См.
[CONFSERVER-95999](https://jira.atlassian.com/browse/CONFSERVER-95999).

## Анонимный доступ {#anonymous-access}

По умолчанию Yahont не считает анонимное содержимое Data Center публичным для всех пользователей Yahont.
Он ограничивает это содержимое пользователями, найденными в Confluence.
Устанавливайте `CONFLUENCE_ANONYMOUS_ACCESS_IS_PUBLIC=true` только если ваша организация хочет,
чтобы анонимное содержимое Confluence было публичным и в Yahont.

## Устранение неполадок в самостоятельно управляемых развёртываниях {#troubleshoot-self-managed-deployments}

| Симптом | Что проверить |
| --- | --- |
| `401 Unauthorized` | Замените PAT и убедитесь, что базовый URL включает контекстный путь. |
| Пространства не найдены | Войдите как аккаунт коннектора и убедитесь, что он может открыть хотя бы одно пространство. |
| Синхронизация прав возвращает `500` в Data Center 9.1+ | Предоставьте права администратора Confluence или администратора пространства для индексируемого пространства. |
| Устаревшая синхронизация прав возвращает `401` | Включите **Remote API (XML-RPC & SOAP)**. |
| Устаревшая синхронизация прав возвращает HTML | Следуйте указаниям по Secure Administrator Sessions выше. Лучше использовать Data Center 9.1+, чем отключать эту настройку безопасности на всём сайте. |
| Некоторые участники групп отсутствуют | Обновитесь до выпуска с исправлением CONFSERVER-95999 и проверьте видимость адресов электронной почты. |
