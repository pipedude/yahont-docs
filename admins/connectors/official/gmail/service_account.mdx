В этом разделе описана настройка коннектора Gmail с помощью сервисного аккаунта.
Подробнее о сервисных аккаунтах [здесь](https://cloud.google.com/iam/docs/service-account-overview).
Нужен Google Workspace.

Если вы предпочитаете использовать аккаунт отдельного человека и OAuth для доступа к Gmail, см. раздел [здесь](./oauth).

### Авторизация {#authorization}

<Steps>
  <Step title="Создайте проект Google Cloud">
    - [https://console.cloud.google.com/projectcreate](https://console.cloud.google.com/projectcreate)
  </Step>

  <Step title="Включите Gmail API и Admin SDK">
    - На левой панели откройте **APIs & services**
    - Перейдите в **Enabled APIs and services**
    - Вверху нажмите **+ENABLE APIS AND SERVICES**
    - Найдите **Gmail API** и нажмите **ENABLE**
    - Либо откройте эту [ссылку](https://console.cloud.google.com/flows/enableapi?apiid=gmail.googleapis.com), выберите свой проект и включите **Gmail API**
    - Также включите **Admin SDK API** (найдите и включите)

    <img className="rounded-image" src="/assets/admins/connectors/google_drive/GoogleDriveEnableAPI.png" alt="Включение Gmail API и Admin SDK в Google Cloud Console"/>
  </Step>

  <Step title="Создайте сервисный аккаунт">
    - Откройте [страницу управления сервисными аккаунтами](https://console.cloud.google.com/iam-admin/serviceaccounts) в Google Cloud.
    - Нажмите кнопку `Create Service Account` и заполните поля на шаге 1. Шаги 2 и 3 можно пропустить.
    - Откройте раздел `Keys` и нажмите `Add Key`. Скачайте этот ключ. Вы передадите его позже при создании учётных данных в Yahont.

    Примечание для организаций Google, созданных после апреля 2024 года:
    - Чтобы предоставить сервисному аккаунту нужные права, перейдите по этой [ссылке](https://console.cloud.google.com/iam-admin/orgpolicies/iam-disableServiceAccountKeyCreation)
    - Затем выберите `Manage`, выберите `Override parent's policy` и затем `Not enforced` в `Rules`.
    - Наконец, выберите `SET POLICY`

  <Step title="Предоставьте делегирование на уровне домена">
    Предоставьте этому **сервисному аккаунту** доступ к Gmail только для чтения
    - Скопируйте `Unique ID` сервисного аккаунта
    - Откройте [страницу Domain-wide Delegation](https://admin.google.com/ac/owl/domainwidedelegation) в Google Admin Console.
    - Нажмите `Add new` и укажите в качестве client ID `Unique ID` сервисного аккаунта
    - Скопируйте этот список областей через запятую и вставьте его в поле `OAuth scopes`:

### Индексирование {#indexing}

Сначала откройте панель администратора и выберите коннектор Gmail.

Затем создайте новые учётные данные. На шаге **Authenticate with Yahont** загрузите ключ сервисного аккаунта,
скачанный при его создании. В каждых учётных данных хранится свой ключ сервисного аккаунта,
поэтому ключ указывается здесь, а не одной загрузкой на весь инстанс.
В качестве **Primary Admin Email** используйте адрес электронной почты пользователя с ролью администратора в Google
Workspace с доступом к привилегиям **Users > Read** и **Groups
> Read**. Это может быть существующий администратор или совершенно новый аккаунт, созданный специально для Yahont (например,
`onyx-robot@your-domain.com`). Обратите внимание: это должен быть *НЕ* адрес электронной почты сервисного аккаунта.
Это может настроить администратор в панели администратора Google Workspace в разделе Account > Admin roles.

Нажмите **Create Credential** и затем закройте диалог. После этого нажмите кнопку **Continue** и настройте коннектор!

<Note>
  В одном инстансе Yahont можно создать несколько учётных данных Gmail, каждые со своим сервисным аккаунтом.
  Это позволяет индексировать несколько Google Workspace из одного развёртывания Yahont.
  Создайте отдельные учётные данные и коннектор для каждого рабочего пространства, которое нужно индексировать.
</Note>
