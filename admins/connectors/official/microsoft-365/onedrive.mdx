title: "OneDrive"
description: "Индексирование файлов из аккаунтов OneDrive пользователей с воспроизведением их доступа Microsoft 365"
---

Коннектор OneDrive индексирует файлы из аккаунтов OneDrive for Business пользователей в вашем тенанте Microsoft 365.
Он сохраняет иерархию папок,
читает изменения после первого запуска и может воспроизводить доступ к каждому файлу с помощью **Auto Sync
Permissions**.

Коннектор входит как регистрация приложения,
настроенная в разделе [Настройка Microsoft 365](/admins/connectors/official/microsoft-365/setup).

## Как это работает {#how-it-works}

| Область | Поведение |
| ---- | -------- |
| Пользователи | Индексируйте всех подходящих пользователей или перечислите конкретные имена участников (UPN) или основные адреса электронной почты. Отключённые пользователи и гости пропускаются. |
| Файлы | Каждый поддерживаемый файл становится одним документом. Папки становятся иерархией, показываемой в Yahont. |
| Обновления | Первый запуск обходит каждый диск. Последующие запуски используют дельта-обновления Microsoft Graph, чтобы читать только изменения. |
| Удаления | Очистка удаляет файлы и папки, которых больше нет или которые больше не входят в область. |
| Права | Необязательно, на платных тарифах. Каждый файл сохраняет владельца, прямой доступ пользователей, доступ групп и доступ по ссылкам для общего доступа. |

## Перед началом {#before-you-begin}

Вам нужен тенант Microsoft 365 с OneDrive for Business и роли,
перечисленные в разделе [Настройка Microsoft 365](/admins/connectors/official/microsoft-365/setup#before-you-begin).
Каждый пользователь должен один раз открыть OneDrive, прежде чем Microsoft создаст его личный диск.
Личные аккаунты Microsoft не поддерживаются.

Выполните [настройку Microsoft 365](/admins/connectors/official/microsoft-365/setup)
со строками OneDrive из её [таблицы разрешений](/admins/connectors/official/microsoft-365/setup#permissions).
Для индексации и синхронизации прав подходят и учётные данные с секретом клиента, и с сертификатом.

## Настройка Yahont {#configure-onyx}

<Steps>
  <Step title="Откройте коннектор OneDrive">
    В Yahont откройте **Панель администратора → Добавить коннектор** и выберите **OneDrive**.
  </Step>

  <Step title="Выберите или создайте учётные данные">
    Выберите существующие учётные данные OneDrive или создайте их,
    как описано в разделе [Настройка Microsoft
    365](/admins/connectors/official/microsoft-365/setup#enter-the-credential-in-onyx).
  </Step>

  <Step title="Выберите пользователей">
    Задайте коннектору понятное название.

    Выберите **General**, чтобы индексировать каждого включённого пользователя, не гостя, с именем участника (UPN).
    Выберите **Specific**, чтобы перечислить имена участников или основные адреса электронной почты.
  </Step>

  <Step title="Настройте расширенные параметры">
    В **Advanced Options** при необходимости добавьте шаблоны glob в **Excluded Paths**. Например,
    `*.tmp` пропускает этот тип файлов на любой глубине, а `Archive/*` пропускает файлы по этому пути.

    Меняйте **Authority Host** и **Graph API Host** только для [национального
    облака](/admins/connectors/official/microsoft-365/setup#national-clouds).
  </Step>

  <Step title="Выберите тип доступа">
    **Public** показывает каждый проиндексированный файл всем пользователям Yahont.
    **Private** ограничивает коннектор выбранными группами Yahont.

    **Auto Sync Permissions** воспроизводит доступ в OneDrive.
    Доступно на тарифах Business и Enterprise в Yahont Cloud и в Enterprise Edition при самостоятельном размещении.
  </Step>

  <Step title="Задайте дату начала индексации">
    В **Advanced Configuration** задайте **Indexing Start Date**, если вам не нужны все файлы. Yahont индексирует файлы,
    созданные или изменённые в эту дату или позже. См.
    [Расширенная конфигурация](/admins/connectors/overview#advanced-configuration).
  </Step>

  <Step title="Подключите и проверьте">
    Нажмите **Create Connector**. Yahont проверяет вход, перечисление пользователей,
    доступ к дискам и доступ к изменениям.
    При синхронизации прав он также проверяет права на файлы и членство в группах Entra.

    Откройте **Панель администратора → Существующие коннекторы**, выберите коннектор и убедитесь,
    что первая попытка индексации завершилась с ожидаемым числом документов.
  </Step>
</Steps>

## Настройки коннектора {#connector-settings}

| Настройка | По умолчанию | Назначение |
| ------- | ------- | ------- |
| Indexing scope | General | **General** охватывает каждого подходящего пользователя. **Specific** охватывает только перечисленных пользователей. |
| Users | пусто | Имена участников (UPN) или основные адреса электронной почты для области **Specific**. |
| Excluded Paths | пусто | Шаблоны glob, сопоставляемые с относительным путём и именем файла. |
| Treat organization links as public | выкл. | При синхронизации прав делает файлы, доступные организации, видимыми каждому пользователю Yahont. Анонимные ссылки всегда публичны. |
| Authority Host | `https://login.microsoftonline.com` | Конечная точка идентификации Microsoft. См. [Национальные облака](/admins/connectors/official/microsoft-365/setup#national-clouds). |
| Graph API Host | `https://graph.microsoft.com` | Конечная точка Microsoft Graph. См. [Национальные облака](/admins/connectors/official/microsoft-365/setup#national-clouds). |

## Автосинхронизация прав {#auto-sync-permissions}

При **Auto Sync Permissions** Yahont предоставляет доступ к файлам:

- Владельцу OneDrive
- Пользователям с прямым доступом
- Членам групп Entra с доступом
- Каждому пользователю Yahont, если у файла есть анонимная ссылка для общего доступа
- Каждому пользователю Yahont, если у файла есть ссылка для всей организации и
  включено **Treat organization links as public**

Адрес электронной почты Microsoft 365 или имя участника (UPN) должны совпадать с адресом пользователя в Yahont.
Yahont раскрывает вложенные группы Entra. Предоставьте **Member.Read.Hidden**,
если в вашем тенанте есть группы со скрытым составом.

Синхронизация документов выполняется каждые 30 минут. Синхронизация групп — каждые 5 минут.
При самостоятельном размещении интервалы можно изменить с помощью `ONEDRIVE_PERMISSION_DOC_SYNC_FREQUENCY` и
`ONEDRIVE_PERMISSION_GROUP_SYNC_FREQUENCY` в секундах.

При **Sites.Selected** предоставьте приложению доступ `read` к каждому личному сайту в области.
Область General может обнаружить всех пользователей, но проиндексировать только личные сайты,
предоставленные приложению. См.
[Ограничение приложения отдельными
сайтами](/admins/connectors/official/microsoft-365/setup#limiting-the-app-to-specific-sites).

## Ограничения {#limits}

| Ограничение | Значение | Примечания |
| ----- | ----- | ----- |
| Размер файла | 20 МБ | Yahont пропускает более крупные файлы. При самостоятельном размещении это можно изменить с помощью `SHAREPOINT_CONNECTOR_SIZE_THRESHOLD` в байтах. |
| Пустые или неподдерживаемые файлы | Пропускаются | Yahont оставляет только те типы файлов, которые поддерживает его обработчик файлов. |
| Область | Личные диски | Для командных сайтов и страниц сайтов используйте [коннектор SharePoint](/admins/connectors/official/microsoft-365/sharepoint). |

## Пересечение с SharePoint {#sharepoint-overlap}

Личный OneDrive опирается на личный сайт SharePoint. Если оба коннектора индексируют один и тот же файл,
Yahont хранит один документ с обоими типами источников,
когда Microsoft Graph возвращает один и тот же ID элемента диска.

Не перечисляйте URL личных сайтов в новом коннекторе SharePoint, если вам не нужно это пересечение.
Microsoft может назначать разные ID элементов копиям на разных дисках, и Yahont индексирует такие копии отдельно.

## Устранение неполадок {#troubleshooting}

Проблемы с учётными данными, согласием, сертификатом и национальным облаком см.
в разделе [Настройка Microsoft 365](/admins/connectors/official/microsoft-365/setup#troubleshooting).

| Сообщение или симптом | Причина и решение |
| ------------------ | ------------- |
| Приложение не может перечислить пользователей тенанта | Предоставьте **User.Read.All** как разрешение приложения Microsoft Graph и дайте согласие администратора. |
| Ни один пользователь не соответствует записи | Используйте имя участника (UPN) или основной адрес электронной почты включённого пользователя-участника. Гости и отключённые пользователи не подходят. |
| Читаемый OneDrive не найден | Предоставьте **Sites.Read.All** или доступ `read` к личному сайту пользователя с **Sites.Selected**. Убедитесь, что у пользователя создан OneDrive. |
| Приложение не может прочитать изменения OneDrive | Приложение может определить пользователя, но не может прочитать диск. Проверьте разрешение на сайт и дождитесь применения нового согласия. |
| Приложение не может прочитать права OneDrive | Разрешение на личный сайт отсутствует или не охватывает файл. Предоставьте **Sites.Read.All** или доступ `read` к выбранному сайту. |
| Приложение не может перечислить или раскрыть группы Entra | Предоставьте **GroupMember.ReadBasic.All**. Добавьте **Member.Read.Hidden** для групп со скрытым составом. |
| У некоторых пользователей возникает сбой, пока запуск продолжается | У этих пользователей нет созданного OneDrive или приложение не может получить доступ к их личным сайтам. Остальные читаемые диски продолжают индексироваться. |
