Сервисный аккаунт — это нечеловеческий пользователь, который существует только для вызовов API Yahont.
Его создание даёт вам API-ключ, позволяющий создавать собственные приложения,
интегрироваться с внешними системами и автоматизировать рабочие процессы.

<Note>
  Сервисный аккаунт — отдельный пользователь в Yahont, поэтому можно отслеживать его активность,
  держать его сессии чата приватными и ограничивать доступные ему ресурсы.
</Note>

## Как сервисный аккаунт получает доступ {#how-a-service-account-gets-its-access}

У сервисного аккаунта нет собственных прав. Его доступ — это сочетание прав всех **групп**, в которые вы его назначили,
точно так же, как у человека.

| Назначенные группы | Что может ключ |
|---|---|
| Нет | Только чат. Может создавать сессии и отправлять сообщения, но не может искать и не имеет доступа ни к одной административной конечной точке. |
| Basic | Чат, поиск, проекты и собственные агенты. |
| Admin | Всё, включая каждую конечную точку `admin/`. |
| Пользовательская группа | Всё, что даёт эта группа. Например, группа с правом **Управление коннекторами и наборами документов** позволяет ключу управлять коннекторами. |

Назначение нескольких групп суммирует их права.

<Tip>
  Если ключ может писать в чат, но поиск ничего не возвращает, проверьте, входит ли его сервисный аккаунт в группу.
</Tip>

О том, как группы и права сочетаются,
читайте в разделе [Как устроены права](/admins/permissions/understanding_permissions).

## Кто может управлять сервисными аккаунтами {#who-can-manage-service-accounts}

Для управления сервисными аккаунтами нужно право **Управление сервисными аккаунтами**,
которое администратор предоставляет группе. У администраторов оно есть всегда.

<Warning>
  Предоставление права **Управление сервисными аккаунтами** равносильно предоставлению Admin.
  Селектор групп намеренно не ограничен, поэтому любой, кто может создать сервисный аккаунт,
  может поместить его в группу Admin и затем использовать его ключ.
</Warning>

## Создание сервисного аккаунта {#creating-a-service-account}

<Steps>
  <Step title="Откройте «Сервисные аккаунты»">
    В панели администратора откройте **Сервисные аккаунты** в разделе **Интеграции**.
  </Step>

  <Step title="Создайте аккаунт">
    Нажмите **Новый сервисный аккаунт**, задайте ему имя и выберите группы, в которые он должен входить.
    Оба значения можно изменить позже.
  </Step>

  <Step title="Сохраните и скопируйте ключ">
    Скопируйте или скачайте ключ, прежде чем закрывать диалог. Yahont показывает его только один раз.
  </Step>
</Steps>

<Warning>
  Не размещайте ключ API в клиентском коде: на страницах сайта и в браузерных приложениях.
  Ключ с правом чата читает все диалоги своего сервисного аккаунта, поэтому любой, кто увидит ключ,
  прочитает диалоги всех пользователей этого ключа. Используйте ключи только на сервере.
</Warning>

## Управление сервисными аккаунтами {#managing-service-accounts}

На странице «Сервисные аккаунты» перечислены все аккаунты с названием, замаскированным ключом и группами.
Для каждого аккаунта можно:

| Действие | Что делает |
|---|---|
| Перевыпустить | Выдаёт новый ключ и отзывает текущий. |
| Группы | Добавляет аккаунт в группы или удаляет из них, что меняет возможности его ключа. |
| Изменить аккаунт | Переименовывает аккаунт или меняет его группы. |
| Удалить аккаунт | Удаляет аккаунт и его ключ. |

<Warning>
  Перевыпуск или удаление ключа нарушит работу любого приложения, которое всё ещё использует старый ключ.
</Warning>

## Персональные токены доступа {#personal-access-tokens}

Сервисные аккаунты предназначены для приложений. Если нужен токен, действующий от имени **человека**,
используйте персональный токен доступа.
Любой пользователь с правом **Создание токена доступа пользователя** может создать его в **Настройки** > **Аккаунты и
доступ**.

Области действия токенов и их использование описаны в разделе [Обзор и
аутентификация](/developers/overview#personal-access-tokens).
