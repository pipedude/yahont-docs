<Info>
  Эта страница относится к версиям Yahont до **4.7**. Для Yahont 4.7 и новее см.
  раздел [Сервисные аккаунты](/admins/user_management/api_keys).
</Info>

API-ключи дают программный доступ к API Yahont: можно создавать собственные приложения,
интегрироваться с внешними системами и автоматизировать рабочие процессы.

<Note>
  API-ключи существуют как отдельные пользователи в Yahont,
  что позволяет отслеживать активность и управлять правами на уровне ключа.
</Note>

## Типы API-ключей {#api-key-types}

Каждый ключ создаётся с ролью, и эта роль определяет, что ему доступно:

<AccordionGroup>
  <Accordion title="API-ключи Admin" icon="shield-check">
    Имеют доступ ко всем конечным точкам, включая те, что начинаются с `admin/`.

    **Сценарии использования:**
    - Полное администрирование системы
    - Операции управления пользователями
    - Управление данными и аналитика
    - Полный доступ ко всем функциям Yahont

    **⚠️ Используйте с осторожностью:** ключи Admin имеют неограниченный доступ к вашему инстансу Yahont.
  </Accordion>

  <Accordion title="API-ключи Basic" icon="key">
    Имеют доступ к неадминистративным конечным точкам, таким как поиск, чат, агенты и действия.

    **Сценарии использования:**
    - Создание чат-приложений
    - Реализация функций поиска
    - Создание агентов и управление ими
    - Запуск действий и рабочих процессов

    **✅ Рекомендуется:** большинству пользователей стоит использовать API-ключи Basic для разработки приложений.
  </Accordion>

  <Accordion title="API-ключи Limited" icon="lock">
    Доступ к агентам только на чтение. Могут отправлять сообщения в конечные точки чата,
    но не могут читать историю чатов.

    **Сценарии использования:**
    - Строго ограниченные среды
    - Специальные случаи, требующие минимальных прав
    - Тестирование с ограниченной областью
  </Accordion>
</AccordionGroup>

<Tip>
  Нужны токены, привязанные к пользователю?
  Любой пользователь может создать [персональный токен доступа](/developers/overview_legacy#personal-access-tokens)
  в **Настройки** > **Аккаунты и доступ**, чтобы аутентифицировать запросы API от своего имени.
</Tip>

## Создание API-ключей {#creating-api-keys}

API-ключи могут создавать и ими могут управлять только администраторы.

<Steps>
  <Step title="Откройте «Сервисные аккаунты»">
    В панели администратора откройте **Сервисные аккаунты**.
  </Step>

  <Step title="Создайте новый API-ключ">
    Нажмите **Новый сервисный аккаунт**, задайте ключу имя и выберите роль для вашего сценария.

    <img className="rounded-image" src="/assets/admins/user_management/legacy/create_api_key.png" alt="Интерфейс создания API-ключа с вариантами ролей Limited, Basic и Admin"/>
  </Step>

  <Step title="Сохраните и скопируйте ключ">
    После создания сразу скопируйте и надёжно сохраните API-ключ. Он показывается только один раз.
  </Step>
</Steps>

Новый API-ключ вместе со всеми существующими ключами отображается на странице «Сервисные аккаунты».

На этой странице можно перевыпускать, переименовывать и удалять API-ключи.

<Warning>
  Перевыпуск ключа отзывает старый. Любое приложение, которое всё ещё его использует, перестанет работать,
  пока вы не передадите ему новый ключ.
</Warning>
