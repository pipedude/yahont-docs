**Terraform-провайдер Yahont** управляет конфигурацией *внутри* работающего развёртывания Yahont: поставщиками LLM,
коннекторами и их учётными данными, наборами документов, агентами, действиями, MCP-серверами, группами пользователей,
API-ключами и настройками рабочего пространства.

Всё, что иначе пришлось бы настраивать кликами в панели администратора, превращается в файл `.tf` под контролем версий,
который можно проверять, сравнивать и применять из CI.

## Две разные области Terraform {#two-different-terraform-surfaces}

У Yahont есть два отдельных предложения для Terraform. Они решают разные задачи и используются в разное время.

| | [Модули Terraform](/deployment/local/terraform) | Terraform-провайдер (эта страница) |
| --- | --- | --- |
| Управляет | **Инфраструктурой**, на которой работает Yahont | **Конфигурацией** внутри Yahont |
| Создаёт | VPC, EKS, RDS, ElastiCache, S3, OpenSearch, WAF | Поставщиков LLM, коннекторы, наборы документов, агентов, группы |
| Распространяется как | Модули в репозитории `onyx`, которые вы копируете и адаптируете | Опубликованный провайдер, который вы объявляете в `required_providers` |
| Обращается к | AWS | Административному API уже работающего развёртывания Yahont |
| Используется | До появления Yahont | После того как Yahont доступен |

<Note>
  Они дополняют друг друга. Создайте инфраструктуру с помощью модулей,
  установите Yahont с помощью [Helm-чарта](/deployment/local/kubernetes),
  затем настройте развёртывание этим провайдером. Их можно запускать из одного корневого модуля,
  но они независимы — провайдер работает с любым доступным развёртыванием Yahont,
  включая [Yahont Cloud](https://cloud.yahont.ai), независимо от способа его развёртывания.
</Note>

## Требования {#requirements}

- **Terraform 1.5 или новее.** [Аргументы секретов только для записи](#keeping-secrets-out-of-state)
  — рекомендуемый способ не хранить учётные данные в состоянии — требуют версии 1.11 или новее,
  а более старый CLI отклонит конфигурацию, которая их использует.
- **Доступное развёртывание Yahont.** Провайдер — это клиент API; он не устанавливает и не обновляет Yahont.
- **API-ключ в группе `Admin`.** Доступ API-ключа определяется членством в группах, поэтому ключ без группы
  не сможет обращаться к административным конечным точкам, которые использует провайдер.

## Получение API-ключа {#get-an-api-key}

Создайте ключ в панели администратора в разделе **API-ключи** — см.
[Сервисные аккаунты](/admins/user_management/api_keys) — и дайте ему административный доступ.
Также подойдёт неограниченный [персональный токен доступа](/developers/overview#personal-access-tokens),
созданный администратором.

API-ключи аутентифицируются одинаково независимо от «человеческого» `AUTH_TYPE` развёртывания (basic, OIDC,
SAML или cloud), а в Yahont Cloud тенант встроен в сам ключ.

<Note>
  С первым ключом возникает проблема курицы и яйца: он должен существовать до запуска Terraform.
  Либо оставьте его неуправляемым, либо позже выполните для него `terraform import`.
  При импорте его атрибут `api_key` остаётся равным null,
  потому что Yahont возвращает материал ключа только при создании.
</Note>

Для автоматической настройки скрипт
[`examples/bootstrap/mint_api_key.sh`](https://github.com/onyx-dot-app/onyx/blob/main/terraform-provider-onyx/examples/bootstrap/mint_api_key.sh)
выполняет всю последовательность: регистрация, вход, определение группы `Admin`, выпуск ключа.

<Warning>
  Скрипт требует указать адрес электронной почты и пароль администратора, а не подставляет их по умолчанию.
  В развёртывании без пользователей он *регистрирует* этот аккаунт,
  а первый зарегистрированный пользователь становится администратором — поэтому пароль по умолчанию тихо создал бы
  администратора с известным паролем в любом доступном развёртывании.
</Warning>

## Настройка провайдера {#configure-the-provider}

```hcl main.tf
terraform {
  required_providers {
    onyx = {
      source  = "onyx-dot-app/onyx"
      version = "~> 0.2"
    }
  }
}

provider "onyx" {
  endpoint = "https://yahont.example.com" # or ONYX_SERVER_URL
  api_key  = var.onyx_api_key           # or ONYX_API_KEY
}
```

<ParamField path="endpoint" type="string">
  Источник сервера Yahont, например `https://cloud.yahont.ai` или `http://localhost:3000`.
  Также читается из `ONYX_SERVER_URL`.
</ParamField>

<ParamField path="api_key" type="string">
  API-ключ (`on_...`) в предустановленной группе `Admin` или неограниченный персональный токен доступа (`onyx_pat_...`).
  Также читается из `ONYX_API_KEY`.
</ParamField>

<ParamField path="api_prefix" type="string" default="/api">
  Префикс пути, под которым доступен API. Значение по умолчанию соответствует веб-прокси. Укажите `""`,
  когда направляете провайдер напрямую на бэкенд, например `http://localhost:8080`. Также читается из `ONYX_API_PREFIX`.
</ParamField>

<Tip>
  Передавайте `api_key` из переменной окружения `ONYX_API_KEY`, а не из файла `.tf`.
  Конфигурация провайдера — единственное место, которое Terraform никогда не записывает в состояние,
  поэтому переменная окружения не даёт ключу попасть ни в ваш репозиторий, ни в файл состояния.
</Tip>

## Пример от начала до конца {#a-worked-example}

Здесь чат-модель связывается с проиндексированным сайтом и агентом, который отвечает на его основе.
Это типичная форма конфигураций: поставщик, учётные данные, коннектор, пара, которая их связывает,
набор документов и агент.

```hcl
resource "onyx_llm_provider" "openai" {
  name          = "openai"
  provider_type = "openai"

  # Write-only: the key never reaches the state file. See below.
  api_key_wo         = var.openai_api_key
  api_key_wo_version = 1

  # The complete set of enabled models: anything omitted is removed on apply.
  model_configurations = [
    { name = "gpt-5" },
    { name = "gpt-5-mini" },
  ]
}

# Referencing the provider id also orders destroys correctly: the default is
# released before the provider holding it is deleted.
resource "onyx_llm_provider_default" "this" {
  provider_id = onyx_llm_provider.openai.id
  model_name  = "gpt-5"
}

# The web connector reads public pages, so its credential holds no secret.
resource "onyx_credential" "web" {
  source          = "web"
  name            = "public-web"
  credential_json = jsonencode({})
}

resource "onyx_connector" "docs" {
  name       = "docs-site"
  source     = "web"
  input_type = "load_state"

  # Re-index once a day.
  refresh_freq = 24 * 60 * 60

  connector_specific_config = jsonencode({
    base_url           = var.docs_base_url
    web_connector_type = "recursive"
  })
}

# The pair is the object that indexes. It also carries the access control for
# the documents it produces.
resource "onyx_cc_pair" "docs" {
  name          = "docs-site"
  connector_id  = onyx_connector.docs.id
  credential_id = onyx_credential.web.id
  access_type   = "public"
}

resource "onyx_document_set" "docs" {
  name        = "docs"
  description = "Public product documentation"
  cc_pair_ids = [onyx_cc_pair.docs.id]
}

resource "onyx_persona" "docs" {
  name        = "Docs"
  description = "Answers product questions from the documentation"

  system_prompt = <<-EOT
    You answer questions from the product documentation.
    If the documentation does not cover the question, say so.
  EOT

  document_set_ids = [onyx_document_set.docs.id]
}
```

Полную рабочую версию этой конфигурации можно найти в
[`examples/bootstrap/`](https://github.com/onyx-dot-app/onyx/tree/main/terraform-provider-onyx/examples/bootstrap).

## Как не хранить секреты в состоянии {#keeping-secrets-out-of-state}

Каждый секрет, который принимает провайдер, существует в двух формах. Обычный атрибут хранится в состоянии Terraform,
и любой, кто может прочитать файл состояния, прочитает секрет.
Двойник `_wo` — это [аргумент только для
записи](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments):
Terraform удаляет значение и из плана, и из состояния, поэтому оно существует только в вашей конфигурации.

**Предпочитайте двойник.** Задавайте либо одно, либо другое, но не оба.

| Ресурс | Хранимый атрибут | Двойник только для записи |
| --- | --- | --- |
| `onyx_llm_provider` | `api_key`, `custom_config` | `api_key_wo`, `custom_config_wo` |
| `onyx_embedding_provider` | `api_key` | `api_key_wo` |
| `onyx_credential` | `credential_json` | `credential_json_wo` |
| `onyx_mcp_server` | `api_token`, `admin_credentials` | `api_token_wo`, `admin_credentials_wo` |
| `onyx_custom_tool` | `custom_headers` | `custom_headers_wo` |

### Ротация секрета только для записи {#rotating-a-write-only-secret}

Значение, которое Terraform никогда не хранит, он не может сравнивать,
поэтому изменение одного `api_key_wo` вообще ничего не планирует.
Для этого у каждого двойника есть счётчик `_wo_version`: увеличьте его,
и получившаяся разница заставит следующее применение отправить актуальный секрет.

```hcl
resource "onyx_llm_provider" "openai" {
  name          = "openai"
  provider_type = "openai"

  api_key_wo         = var.openai_api_key
  api_key_wo_version = 2 # was 1 — bump after rotating the key

  model_configurations = [{ name = "gpt-5-mini" }]
}
```

<Warning>
  Не вычисляйте счётчик из секрета — `md5(var.token)` и подобное. В отличие от секрета, счётчик *хранится* в состоянии.
</Warning>

Два атрибута не могут иметь двойника только для записи. `onyx_api_key.api_key` выпускается самим Yahont,
а не задаётся вами, поэтому Terraform может вернуть его только через состояние — считайте,
что файл состояния его содержит. `onyx_mcp_server.auth_template_headers` вычисляется Yahont,
а Terraform не позволяет аргументу быть одновременно вычисляемым и только для записи.

<Tip>
  Независимо от используемой формы, шифруйте состояние Terraform и ограничьте круг тех, кто может его читать.
  Несколько ресурсов содержат учётные данные систем далеко за пределами Yahont.
</Tip>

## Enterprise Edition {#enterprise-edition}

Большая часть провайдера работает в Community Edition. Для этих частей нужна Enterprise Edition:

- `onyx_user_group` — маршруты находятся в приложении Enterprise и отвечают 404 в Community Edition.
- `users` и `groups` в `onyx_document_set` и `onyx_persona` — Community Edition отклоняет приватный набор или агента.

<Info>
  **Функция Enterprise Edition**

  Эти функции доступны только в Enterprise Edition. Чтобы узнать больше, [напишите нам](mailto:support@yahont.ai).
</Info>

## Что API выразить не может {#things-the-api-cannot-express}

Некоторые особенности поведения идут от API Yahont, а не от провайдера, и о них стоит знать,
прежде чем на них полагаться:

- **Дрейф секретов невидим.** API маскирует секреты при чтении,
  поэтому ротация секрета в панели администратора не отображается в `terraform plan`.
  Настроенное значение считается эталонным и заново применяется при следующем применении.
- **`onyx_settings` и `onyx_llm_provider_default` на самом деле не удаляются.** В Yahont нет API сброса для них, поэтому
  `destroy` убирает их из состояния с предупреждением и не трогает действующие значения.
- **`model_configurations` — основной список.** Модель, которой в нём нет, удаляется из поставщика на стороне сервера.
- **Удаление агента оставляет «надгробие».** Имя остаётся занятым, и последующее создание с этим именем возрождает
  того же агента с прежним id, а не создаёт нового.
- **Удаление пользовательского действия отсоединяет его от каждого агента, который его использует**, включая агентов,
  которыми Terraform не управляет, без ошибок и предупреждений.

[README
провайдера](https://github.com/onyx-dot-app/onyx/tree/main/terraform-provider-onyx#known-limitations-by-api-design)
содержит полный список, а страница каждого ресурса в реестре повторяет те пункты, которые к нему относятся.
