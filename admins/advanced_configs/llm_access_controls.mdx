## Обзор {#overview}

Yahont предлагает детальное управление доступом к поставщикам языковых моделей: администраторы могут решать,
**кто** может использовать конкретные модели и **какие агенты** могут с ними работать.
Это даёт лучший контроль расходов, управление и соблюдение политик использования моделей.

<Info>
  Ограничения по группам пользователей требуют пользовательских групп, а они — функция Enterprise Edition.
</Info>

### Типы управления доступом {#access-control-types}

<AccordionGroup>
  <Accordion title="Публичные и приватные поставщики" icon="lock">
    **Публичные поставщики**
    - Доступны всем пользователям и агентам
    - Никаких ограничений
    - Подходят для моделей по умолчанию без ограничений

    **Приватные поставщики**
    - Подчиняются ограничениям по группам пользователей и (или) агентам
    - Позволяют детально управлять доступом
    - Рекомендуются для дорогих и специализированных моделей
  </Accordion>

  <Accordion title="Ограничения по группам пользователей" icon="users">
    Управляйте тем, **кто** может использовать конкретных поставщиков языковых моделей,
    ограничивая доступ определёнными группами пользователей.

    **Как это работает:**
    - Назначьте поставщику одну или несколько групп пользователей
    - Использовать поставщика могут только пользователи из этих групп
    - Администраторы обходят ограничения по группам (но не ограничения по агентам)
    - Оставьте пустым, чтобы не ограничивать по группам

    **Сценарии использования:**
    - Ограничить дорогие модели определёнными командами
    - Предоставить специализированные модели отдельным отделам
    - Контролировать расходы по командам
  </Accordion>

  <Accordion title="Ограничения по агентам" icon="robot">
    Управляйте тем, **какие агенты** могут использовать конкретных поставщиков языковых моделей.

    **Как это работает:**
    - Назначьте поставщику одного или нескольких агентов через «Белый список агентов»
    - Поставщик будет отображаться как вариант только при работе с этими агентами
    - Действует для **всех пользователей**, включая администраторов
    - Оставьте пустым, чтобы не ограничивать по агентам

    **Сценарии использования:**
    - Зарезервировать GPT-4 только для «Агента проверки кода»
    - Использовать Claude Opus только с «Анализатором юридических документов»
    - Не дать пользователям выбирать неподходящие модели для конкретных сценариев
    - Применять политики использования моделей по типам агентов
  </Accordion>

  <Accordion title="Комбинированные ограничения" icon="layer-group">
    Для максимального контроля можно сочетать ограничения по группам пользователей и по агентам.

    **Правила доступа (логика И):**
    - Пользователь должен входить в разрешённую группу **И** использовать разрешённого агента
    - Для доступа должны выполняться оба условия
    - Администраторы обходят ограничения по группам, но им всё равно нужны разрешённые агенты

    **Пример:**
    - Поставщик: GPT-4
    - Группы пользователей: «Команда разработки»
    - Белый список агентов: «Агент проверки кода», «Консультант по архитектуре»
    - **Результат:** GPT-4 могут использовать только члены команды разработки и только с этими двумя агентами
  </Accordion>
</AccordionGroup>

### Настройка управления доступом {#configuring-access-controls}

Чтобы настроить управление доступом для поставщика языковых моделей:

<Steps>
  <Step title="Откройте «Языковые модели»">
    Перейдите в **Панель администратора → Языковые модели**
  </Step>

  <Step title="Выберите поставщика">
    Нажмите на существующего поставщика или создайте нового
  </Step>

  <Step title="Настройте управление доступом">
    В разделе **Управление доступом** в расширенных параметрах:
    - Отключите **Сделать публичным**, чтобы включить ограничения
    - Выберите группы пользователей в **Доступ для групп пользователей** (необязательно)
    - Выберите агентов в **Белом списке агентов** (необязательно)
  </Step>

  <Step title="Сохраните изменения">
    Сохраните изменения
  </Step>
</Steps>

<Note>
  Если поставщик публичный, элементы выбора для управления доступом автоматически отключаются.
</Note>

### Логика принятия решения о доступе {#access-decision-logic}

Система определяет доступ по следующей логике:

| is_public | Группы заданы | Агенты заданы | Правило доступа |
|-----------|------------|------------|-------------|
| `true` | Любые | Любые | Доступ у всех |
| `false` | Да | Да | Нужно состоять в группе **И** использовать разрешённого агента |
| `false` | Да | Нет | Нужно состоять в группе (администраторы обходят) |
| `false` | Нет | Да | Нужно использовать разрешённого агента (действует и для администраторов) |
| `false` | Нет | Нет | Доступ только у администраторов |

### Видимость поставщиков {#provider-visibility}

Пользователи видят только тех поставщиков языковых моделей, к которым у них есть доступ:
- В интерфейсе создания и редактирования агента
- В списке моделей интерфейса чата
- При получении списка доступных поставщиков через API

Поставщики с ограничениями полностью скрыты от пользователей, у которых нет доступа,
что исключает путаницу и попытки несанкционированного использования.
