Подключите ИИ-клиент к Yahont, чтобы искать доступные вам документы, искать в интернете и получать текст веб-страниц.
Клиент использует результаты поиска Yahont, чтобы ответить на ваш вопрос в разговоре, где вы уже работаете.

OAuth позволяет подключиться, войдя в Yahont и одобрив приложение.
Копировать персональный токен доступа в настройки клиента не нужно.
Персональные токены доступа и ключи API остаются доступными для аутентификации Bearer.

<Note>
  Это руководство описывает Yahont как MCP-**сервер**, который даёт внешним клиентам доступ к поиску Yahont.
  Чтобы дать агентам Yahont инструменты другого MCP-сервера, см. [плагины MCP](/admins/plugins/mcp).
</Note>

## Перед подключением {#before-you-connect}

- Спросите у администратора адрес MCP Yahont, например `https://your-yahont-domain.com/mcp/`.
- Войдите под своим аккаунтом Yahont в рабочее пространство, по документам которого хотите искать.
- Чтобы одобрить приложение, вашему аккаунту нужны права **Поиск** (`read:search`) и **Создание токена доступа
  пользователя** (`create:user_api_keys`).
- Администратор должен включить MCP-сервер. В Yahont CE он по умолчанию выключен: см.
  [руководство по включению](/deployment/configuration/mcp_server#enable-the-service).
  Для OAuth в развёртываниях с самостоятельным размещением нужен HTTPS,
  для локальной разработки поддерживается HTTP на loopback.
- Используйте клиент, который поддерживает удалённые MCP-серверы Streamable HTTP и OAuth.

В примерах в качестве заглушки используется `your-yahont-domain.com`. Замените его веб-адресом вашего Yahont.
Используйте один и тот же URL во всех настройках клиента.

## Подключение ИИ-инструментов {#connect-your-ai-tools}

Укажите адрес MCP вашего Yahont в настройках клиента. Когда клиент попросит,
пройдите [вход в Yahont и одобрение](#sign-in-and-approve-access).

### Codex {#codex}

#### Добавьте Yahont и войдите {#add-onyx-and-sign-in}

Выполните эти команды в терминале, заменив адрес из примера:

```bash
codex mcp add yahont --url https://your-yahont-domain.com/mcp/
codex mcp login yahont
```

Пройдите вход и одобрение в Yahont в браузере. Затем проверьте конфигурацию и запустите Codex:

```bash
codex mcp list
codex
```

В Codex введите `/mcp` и убедитесь, что Yahont подключён. Отправьте [тестовый запрос](#test-the-connection),
чтобы убедиться, что поиск работает.

#### Настройка через TOML {#configure-with-toml}

Вместо `codex mcp add` добавьте следующее в `~/.codex/config.toml`:

```toml
[mcp_servers.yahont]
url = "https://your-yahont-domain.com/mcp/"
```

После сохранения выполните `codex mcp login yahont`. Оставьте в файле одну таблицу `mcp_servers.yahont`.
Если Yahont уже есть в файле, обновите его URL, а не добавляйте вторую таблицу.

Настольное приложение, CLI и расширение для IDE используют общую конфигурацию на одном хосте Codex.
Варианты настройки см. в [руководстве OpenAI по MCP](https://learn.chatgpt.com/docs/extend/mcp).

### Claude Code {#claude-code}

#### Добавьте Yahont для своей учётной записи {#add-onyx-for-your-user-account}

```bash
claude mcp add --scope user --transport http yahont https://your-yahont-domain.com/mcp/
claude
```

В Claude Code введите `/mcp`, выберите Yahont и нажмите **Authenticate**. Завершите одобрение в браузере.
Снова проверьте `/mcp` и отправьте [тестовый запрос](#test-the-connection).

Актуальные выпуски также поддерживают аутентификацию прямо из терминала:

```bash
claude mcp login yahont
```

Команда `claude mcp list` показывает настроенные серверы. Об аутентификации и областях конфигурации см.
[документацию Claude Code по MCP](https://code.claude.com/docs/en/mcp).

#### Общая конфигурация для проекта {#share-the-configuration-with-a-project}

Для командного репозитория укажите адрес в `.mcp.json` в корне проекта:

```json
{
  "mcpServers": {
    "yahont": {
      "type": "http",
      "url": "https://your-yahont-domain.com/mcp/"
    }
  }
}
```

Каждый участник команды одобряет конфигурацию проекта и входит под своим аккаунтом Yahont.
Коммитьте только настройку адреса. Учётные данные OAuth в репозитории хранить нельзя.
Выберите для Yahont либо конфигурацию пользователя, либо конфигурацию проекта, чтобы определения не конфликтовали.

### Claude Desktop {#claude-desktop}

Используйте удалённый пользовательский коннектор:

1. Откройте **Customize > Connectors**.
2. Выберите **+ Add > Add custom connector**.
3. Назовите его **Yahont** и введите `https://your-yahont-domain.com/mcp/` с вашим доменом.
4. Продолжите настройку аутентификации.
   Выберите вход и либо опубликованный OAuth-идентификатор Claude, либо автоматическую регистрацию.
   Yahont поддерживает оба.
5. Добавьте коннектор и пройдите вход в Yahont, когда он потребуется.
6. Включите Yahont через меню **+ > Connectors** в разговоре и отправьте [тестовый запрос](#test-the-connection).

Для управляемой организации владелец добавляет Yahont в **Organization settings > Connectors**.
Затем участники нажимают **Connect** у Yahont в своём списке коннекторов и одобряют доступ своим аккаунтом.

<Note>
  Удалённые коннекторы Claude Desktop подключаются из облака Anthropic.
  Ваш сервер должен быть доступен из этой инфраструктуры, даже если ваш ноутбук видит его через VPN.
  JSON-конфигурация настольного приложения для локальных процессов — это отдельный механизм настройки.
</Note>

Актуальную доступность и требования к сети см.
в [руководстве Anthropic по пользовательским
коннекторам](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

### ChatGPT desktop {#chatgpt-desktop}

1. Откройте **Settings > MCP servers** и выберите **Add server**.
2. Назовите его **Yahont** и выберите **Streamable HTTP**.
3. Введите `https://your-yahont-domain.com/mcp/` с вашим доменом.
4. Сохраните, затем выберите **Restart**.
5. Выберите **Authenticate** у Yahont и пройдите вход и одобрение в браузере.
6. Введите `/mcp` в поле ввода, чтобы посмотреть подключённые серверы, затем отправьте
   [тестовый запрос](#test-the-connection).

Если вы уже настроили Yahont в Codex на этом же хосте, посмотрите список серверов, прежде чем добавлять его снова.
Эти клиенты используют общий `~/.codex/config.toml`. Актуальные элементы управления настольного приложения см.
в [руководстве OpenAI по MCP](https://learn.chatgpt.com/docs/extend/mcp).

#### ChatGPT в вебе {#chatgpt-on-the-web}

Веб-версия ChatGPT использует размещённые инструменты MCP через плагины.
Она не читает вашу локальную конфигурацию Codex.
Поэтому добавление Yahont в настольное приложение не настраивает его в вебе.
Модель веб-подключения и доступность плагинов в вашем рабочем пространстве описаны в [руководстве OpenAI по
MCP](https://learn.chatgpt.com/docs/extend/mcp).

## Вход и одобрение доступа {#sign-in-and-approve-access}

<Steps>
  <Step title="Добавьте адрес MCP вашего Yahont">
    Укажите URL в клиенте по [инструкциям для клиентов](#connect-your-ai-tools).
    Выберите OAuth или действие аутентификации клиента. Не добавляйте заголовки с токеном Bearer в конфигурацию OAuth.
  </Step>

  <Step title="Войдите в Yahont">
    Клиент откроет браузер. При необходимости войдите обычным для вас способом входа в Yahont.
    Одобрение выполняет обычная учётная запись пользователя.
    Ключ API или сервисный аккаунт не могут одобрить подключение OAuth.
  </Step>

  <Step title="Проверьте подключение">
    Yahont покажет **Подключение к Yahont** и спросит, разрешить ли приложению искать в Yahont.
    Проверьте название приложения, аккаунт, под которым вы вошли, рабочее пространство и адрес приложения,
    затем выберите **Разрешить доступ**. Выберите **Отклонить**, чтобы вернуться в клиент без предоставления доступа.
  </Step>

  <Step title="Вернитесь в клиент">
    Клиент завершит вход и сохранит учётные данные. Убедитесь, что инструменты Yahont появились, затем попробуйте поиск.
    Одной настроенной записи сервера недостаточно, чтобы считать, что аутентификация и поиск работают.
  </Step>
</Steps>

### Проверка подключения {#test-the-connection}

Скопируйте этот запрос в клиент:

```text
Используй MCP-сервер Yahont и найди наше руководство по адаптации новых сотрудников.
Верни названия подходящих документов и ссылки на источники.
Если у тебя нет доступа к Yahont или ты не нашёл подходящий документ, скажи об этом прямо.
```

Проверьте, что клиент вызывает `search_indexed_documents`. Результаты должны содержать названия документов,
ссылки на источники и найденное содержимое. Пустой результат может быть корректным ответом поиска: попробуйте документ,
к которому у вас точно есть доступ в Yahont.

## Права и доступ к данным {#permissions-and-data-access}

Подключение OAuth получает область `read:search`. Оно может искать по доступным вам документам,
читать ресурсы с метаданными поиска, искать в публичном интернете и открывать веб-страницы.
Оно не может создавать ключи API, одобрять другие приложения и использовать несвязанные API Yahont.
Право создавать токены доступа пользователя — это условие одобрения, а не дополнительная область, выдаваемая приложению.

Ваши права на документы и политики рабочего пространства продолжают действовать.
Подключение приложения не даёт доступа к документам, которые вы не можете читать. Членство в рабочем пространстве,
доступ аккаунта, ограничения оплаты и лимиты использования могут влиять на запросы после подключения.

Ваш внешний ИИ-клиент получает найденное содержимое, чтобы использовать его в ответе. Выбирайте клиент и аккаунт,
которым ваша организация разрешает получать такую информацию. Yahont находит содержимое,
а окончательный ответ пишет внешний клиент.

## Срок действия подключения {#connection-expiry}

| Учётные данные | Срок действия |
| --- | --- |
| Токен доступа | 15 минут. Клиент обычно обновляет его автоматически. |
| Авторизация OAuth с поддержкой обновления | 30 дней с момента одобрения. Обновление не продлевает этот срок. |

После окончания срока авторизации войдите и одобрите доступ снова. Refresh token ротируются после использования.
Повторное использование уже использованного refresh token отзывает эту авторизацию, поэтому клиенту,
который потерял или повторно использовал свои refresh-данные, может потребоваться, чтобы вы подключились заново.

Если клиент зарегистрировался без поддержки обновления, его авторизация действует только в течение срока токена доступа.

Для подключения по персональному токену доступа или ключу API отзовите токен или ключ.

## Использование персонального токена доступа {#use-a-personal-access-token-instead}

OAuth — обычная настройка для интерактивных клиентов. Если вашей среде нужен токен Bearer,
создайте [персональный токен доступа](/developers/overview#personal-access-tokens) с доступом `read:search`.

Храните токен в локальной переменной окружения.
В Bash так можно прочитать его без вывода на экран и без попадания значения в историю команд:

```bash
read -r -s -p "Yahont personal access token: " ONYX_TOKEN
printf '\n'
export ONYX_TOKEN
```

Запускайте клиент из этой оболочки. Переменная живёт до конца сеанса оболочки.
Для постоянной настройки используйте одобренный в вашей организации способ хранения секретов на локальной машине.

### Настройка Codex с токеном {#codex-token-configuration}

Используйте эту таблицу вместо таблицы только для OAuth:

```toml
[mcp_servers.yahont]
url = "https://your-yahont-domain.com/mcp/"
bearer_token_env_var = "ONYX_TOKEN"
```

Запускайте `codex` из оболочки, где экспортирован `ONYX_TOKEN`. Настольное приложение, запущенное отдельно,
может не унаследовать окружение этой оболочки.

### Настройка Claude Code с токеном {#claude-code-token-configuration}

Используйте эту запись `.mcp.json` вместо записи только для OAuth:

```json
{
  "mcpServers": {
    "yahont": {
      "type": "http",
      "url": "https://your-yahont-domain.com/mcp/",
      "headers": {
        "Authorization": "Bearer ${ONYX_TOKEN}"
      }
    }
  }
}
```

Запускайте `claude` из оболочки, где экспортирована переменная.
Claude Code подставляет значение переменной окружения при загрузке конфигурации. Удалите заголовок Authorization,
чтобы вернуться к OAuth.

## Отключение и смена аккаунта {#disconnect-or-change-accounts}

Чтобы удалить сохранённые учётные данные OAuth в Codex:

```bash
codex mcp logout yahont
```

Чтобы удалить конфигурацию его сервера:

```bash
codex mcp remove yahont
```

Для Claude Code:

```bash
claude mcp logout yahont
claude mcp remove yahont --scope user
```

Если вы использовали конфигурацию проекта, удалите запись Yahont из `.mcp.json`.
Настройки настольных коннекторов тоже содержат элементы отключения или удаления.

Удаление конфигурации клиента и отзыв авторизации Yahont — разные операции.
Используйте [элементы управления подключёнными приложениями Yahont](#manage-connected-apps), чтобы отозвать грант.
Если вы использовали аутентификацию по токену, отзовите персональный токен доступа в Yahont. Чтобы сменить аккаунт,
очистите сохранённую аутентификацию клиента и подключитесь заново под нужным аккаунтом Yahont.

## Примеры запросов {#prompts-you-can-use}

Замените названия и даты значениями из вашего рабочего пространства. Просите ссылки на источники,
чтобы проверить материалы, на которых основан ответ.

### Найти процедуру {#find-a-procedure}

```text
Найди в Yahont нашу процедуру отката развёртывания.
Кратко изложи шаги из найденных документов и приведи ссылку на источник для каждого шага.
Отметь недостающие или противоречивые инструкции, а не заполняй пробелы сам.
```

### Поиск по набору документов {#search-a-document-set}

```text
Используй Yahont и ищи чек-лист выпуска только в наборе документов «Инженерные руководства».
Передай это название через фильтр document_set_names.
Если такого названия нет, покажи предложенные названия и спроси, какое использовать.
Не повторяй поиск без фильтра по набору документов.
```

### Использовать область знаний агента Yahont {#use-an-onyx-agents-knowledge-scope}

```text
Найди в Yahont чек-лист развёртывания с помощью агента «Инженерная поддержка».
Передай название агента через параметр agent, чтобы поиск использовал область знаний этого агента.
Укажи исходные документы. Если агента найти не удалось, попроси меня выбрать из доступных агентов.
```

Так выполняется поиск с областью знаний и настроенной моделью агента. Чат с этим агентом не запускается.
Не комбинируйте `agent` и `document_set_names` в одном поиске.

### Найти недавно обновлённые документы {#find-recently-updated-documents}

```text
Найди в Yahont примечания к выпускам среди документов GitHub, обновлённых 1 октября 2026 UTC или позже.
Используй source_types ["github"] и time_cutoff "2026-10-01T00:00:00Z".
Верни названия документов, даты обновления и ссылки на источники.
```

Фильтр по дате применяется ко времени обновления документов, а не к датам, упомянутым в тексте.

### Сравнить рекомендации рабочего пространства с публичной документацией {#compare-workspace-guidance-with-public-documentation}

```text
Найди в Yahont нашу процедуру обновления зависимостей Python.
Затем найди через веб-поиск Yahont соответствующую публичную документацию пакета
и открой нужные публичные страницы, если фрагментов недостаточно для ответа.
Держи нашу процедуру и публичные рекомендации раздельно, со ссылками для каждой.
```

## Справочник инструментов {#tool-reference}

### search_indexed_documents {#search_indexed_documents}

Поиск по знаниям, проиндексированным в Yahont. Поиск включает расширение запроса, извлечение,
отбор документов и расширение контекста.

| Параметр | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `query` | string | Да | Вопрос или поисковый запрос. |
| `source_types` | массив строк | Нет | Идентификаторы коннекторов, например `github` или `google_drive`. |
| `document_set_names` | массив строк | Нет | Названия доступных наборов документов. |
| `time_cutoff` | string | Нет | Метка времени ISO 8601. Оставляет документы, обновлённые в это время или позже. Укажите часовой пояс. |
| `skip_query_expansion` | boolean | Нет | По умолчанию `false`. Задайте `true`, чтобы пропустить расширение запроса. |
| `agent` | string | Нет | Название доступного агента Yahont, чью область знаний и модель должен использовать поиск. |

```json
{
  "query": "How do I roll back a deployment?",
  "source_types": ["github"],
  "document_set_names": ["Engineering guides"],
  "time_cutoff": "2026-10-01T00:00:00Z",
  "skip_query_expansion": false
}
```

Названия наборов документов и агентов должны существовать в вашем рабочем пространстве. Неизвестные типы источников,
наборы документов или агенты возвращают ошибку с предложенными или доступными значениями.
Исправьте фильтр перед повторной попыткой. Пустые массивы фильтров не ограничивают поиск.
Используйте корректную метку времени: неверный `time_cutoff` может привести к поиску без ограничения по дате.

В ответе есть массив `results`. Каждый результат содержит `title`, `url`, `source_type`, `content` и `updated_at`.
Результаты упорядочены по релевантности. `content` содержит найденный текст документа,
это может быть выбранный фрагмент, а не весь документ. Параметра `limit` у этого инструмента нет.

### search_web {#search_web}

Поиск по публичному вебу. Доступность зависит от настройки веб-поиска в вашем Yahont.

| Параметр | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `query` | string | Да | Запрос для поиска в публичном вебе. |
| `limit` | integer | Нет | Максимальное число запрашиваемых результатов. По умолчанию `5`. |

```json
{
  "query": "Python packaging dependency constraints documentation",
  "limit": 5
}
```

Ответ содержит `results` и `query`. Результаты включают заголовки страниц, URL и фрагменты. Используйте `open_urls`,
чтобы получить текст страницы, когда фрагмента недостаточно.

### open_urls {#open_urls}

Получение текста веб-страниц. Этот инструмент не позволяет обойти вход на сайт или права доступа к документам Yahont.

| Параметр | Тип | Обязателен | Описание |
| --- | --- | --- | --- |
| `urls` | массив строк | Да | URL для получения. По умолчанию не больше 20 за вызов. |

```json
{
  "urls": ["https://docs.python.org/3/library/venv.html"]
}
```

Ответ содержит массив `results` с полученным текстом страниц и метаданными.

## Справочник ресурсов {#resource-reference}

Клиенты, которые поддерживают ресурсы MCP, могут читать эти JSON-ресурсы, чтобы узнать доступные фильтры поиска:

| Ресурс | Ответ | Назначение |
| --- | --- | --- |
| `resource://indexed_sources` | Массив идентификаторов источников. | Используйте идентификаторы в `source_types`. |
| `resource://document_sets` | Массив доступных наборов документов с `name` и `description`. | Используйте названия в `document_set_names`. |
| `resource://agents` | Массив доступных агентов с `id`, `name` и `description`. | Используйте названия в `agent`. |

Поддержка ресурсов зависит от клиента. Обращаться к ресурсу перед поиском не обязательно:
именованные фильтры разрешаются при вызове поиска и возвращают ошибку, если их не удалось разрешить.

## Устранение неполадок {#troubleshooting}

| Проблема | Что проверить |
| --- | --- |
| Вход не открывается или сервер недоступен | Проверьте URL MCP и то, что клиент поддерживает OAuth по HTTP. Попросите администратора проверить [обнаружение и маршрутизацию](/deployment/configuration/mcp_server#verify-the-deployment). |
| Одобрение запрещено | Убедитесь, что вы вошли как обычный пользователь в нужное рабочее пространство и у вас есть права «Поиск» и «Создание токена доступа пользователя». |
| Аутентификация истекает или возвращает `401` | Пройдите аутентификацию снова. Возможно, истекла 30-дневная авторизация или приложение было отключено. |
| Доступ запрещён или возвращается `403` | Проверьте текущие права, членство в рабочем пространстве и область `read:search`. Повторный вход не вернёт право, которого у вашего аккаунта больше нет. |
| Запрос возвращает `402` | Попросите администратора проверить ограничения оплаты или лицензии. |
| Запрос возвращает `503` | Нужный сервис недоступен. Повторите позже и попросите администратора проверить состояние сервисов, если проблема не проходит. |
| Нужного документа нет | Убедитесь, что вы находите его в Yahont, что он проиндексирован и что фильтры соответствуют его источнику, набору документов и времени обновления. |
| Именованный фильтр не работает | Используйте предложенные или доступные названия. Сохраняйте фильтр, если поиск должен оставаться в этой области. |
| Настольный коннектор не может подключиться к инстансу с самостоятельным размещением | Размещённые коннекторы могут подключаться из облачной инфраструктуры. URL, доступного только с вашего ноутбука, для таких клиентов недостаточно. |
| Нет раздела «Подключённые приложения» | Попросите администратора убедиться, что в вашем развёртывании есть поддержка OAuth и задан поддерживаемый веб-адрес. Подключения по персональному токену управляются как токены, а не как подключённые приложения OAuth. |

Команды подключения см. в разделе [Подключение ИИ-инструментов](#connect-your-ai-tools).
