Agent Wiki предоставляет себя как сервер [Model Context Protocol](https://modelcontextprotocol.io),
поэтому любой агент с поддержкой MCP может искать, читать, редактировать и комментировать страницы вики так же, как вы.
Вики становится общей памятью ваших агентов: они загружают из неё контекст перед работой и записывают обратно то,
что узнали.

Агент действует **от вашего аккаунта, с вашими правами**. Он может обращаться ровно к тем страницам,
к которым можете обращаться вы.

## Получение учётных данных {#get-your-credentials}

Откройте **Agents & Actions** на левой боковой панели.

<Steps>
  <Step title="Скопируйте URL сервера MCP">
    Конечная точка — это источник вашей вики с добавлением `/api/mcp`, например `https://wiki.example.com/api/mcp`.
  </Step>

  <Step title="Создайте ключ API">
    Нажмите **Generate API key** и назовите ключ по имени устройства или агента,
    который будет его использовать (`claude-code-laptop`). Сразу скопируйте значение `mcp_…`.

    <Warning>
      Ключ показывается **один раз**. Если вы его потеряете, создайте другой и отзовите старый на той же странице.
    </Warning>
  </Step>
</Steps>

## Подключение агента {#connect-your-agent}

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http agent-wiki \
      https://wiki.example.com/api/mcp \
      --header "Authorization: Bearer mcp_REPLACE_ME"
    ```

    <Warning>
      **Порядок аргументов важен.** URL должен стоять сразу после имени, а `--header` — последним.
      `--header` принимает переменное число значений,
      поэтому URL после него воспринимается как ещё одно значение заголовка, и вы получаете `error:
      missing required argument 'commandOrUrl'`.
    </Warning>

    Добавьте `-s user`, чтобы вики была доступна в каждом проекте. Без него сервер регистрируется только для каталога,
    в котором вы выполнили команду, а `claude mcp get` из любого другого места сообщает «No MCP server found».

    Подтвердите подключение командой `claude mcp get agent-wiki` (или `/mcp` внутри сессии) — должно быть `Status:
    ✓ Connected`.

    Чтобы поделиться подключением с репозиторием, добавьте в него `.mcp.json`:

    ```json
    {
      "mcpServers": {
        "agent-wiki": {
          "type": "http",
          "url": "https://wiki.example.com/api/mcp"
        }
      }
    }
    ```

    Перезапустите Claude Code или выполните `/mcp` после изменения `.mcp.json`.
  </Tab>

  <Tab title="Cursor">
    Добавьте сервер в `~/.cursor/mcp.json`:

    ```json
    {
      "mcpServers": {
        "agent-wiki": {
          "url": "https://wiki.example.com/api/mcp",
          "headers": { "Authorization": "Bearer mcp_REPLACE_ME" }
        }
      }
    }
    ```
  </Tab>

  <Tab title="Codex CLI">
    Добавьте сервер в `~/.codex/config.toml`:

    ```toml
    [mcp_servers.agent-wiki]
    url = "https://wiki.example.com/api/mcp"
    headers = { Authorization = "Bearer mcp_REPLACE_ME" }
    ```
  </Tab>

  <Tab title="Yahont Craft">
    В Yahont агент, который работает с серверами MCP, — это **Craft**. Подключение состоит из двух частей:
    администратор один раз регистрирует вики для организации, затем каждый человек подключает свой ключ.

    **Администратор — регистрация вики (один раз)**

    <Steps>
      <Step title="Добавьте сервер MCP">
        В панели администратора откройте **Действия MCP → Добавить сервер MCP** и введите URL MCP вашей вики.
        Полный справочник по полям см. в разделе [Действия MCP](/admins/actions/mcp).
      </Step>

      <Step title="Выберите аутентификацию по ключу API">
        Выберите **Индивидуальный ключ**,
        чтобы каждый человек использовал собственный ключ `mcp_…` — это удерживает агента каждого пользователя в
        границах его собственных прав в вики. **Общий ключ** даёт всем доступ того аккаунта, который его создал.
      </Step>

      <Step title="Выберите инструменты для предоставления">
        Yahont показывает инструменты вики и позволяет выбрать, какие из них доступны агентам по всей организации.
      </Step>

      <Step title="Включите для Craft">
        Откройте **Панель администратора → Craft → Приложения** и включите вики.
        Карточка должна показывать «Available to the Craft agent — tool calls follow their approval policies».
        Пока это не включено, Craft вообще не видит вики.
      </Step>
    </Steps>

    **Каждый пользователь — подключение (один раз)**

    Откройте **Craft → Приложения**, найдите вики,
    нажмите **Подключить** и вставьте ваш ключ API из **Agents & Actions**. Учётные данные общие для всех интерфейсов:
    подключитесь в Craft — и вы подключены также в чате, и наоборот.

    <Note>
      Вызовы инструментов Craft ограничиваются по каждому инструменту на границе песочницы.
      По умолчанию агент спрашивает перед каждым вызовом;
      администраторы могут задать для инструмента «всегда разрешать» или «запретить» на странице администрирования MCP.
    </Note>
  </Tab>

  <Tab title="Claude Desktop">
    Claude Desktop — **непроверенный способ настройки**.
    `claude_desktop_config.json` принимает только локальные записи серверов STDIO (`command`, `args`, `env`),
    а не удалённые записи HTTP с `url` и `headers`.

    Если вы всё же хотите попробовать, используйте мост через `mcp-remote` и храните значение bearer в `env`,
    чтобы избежать проблем с экранированием заголовков в macOS:

    ```json
    {
      "mcpServers": {
        "agent-wiki": {
          "command": "npx",
          "args": [
            "mcp-remote",
            "https://wiki.example.com/api/mcp",
            "--header",
            "Authorization:${AGENT_WIKI_AUTH}"
          ],
          "env": { "AGENT_WIKI_AUTH": "Bearer mcp_REPLACE_ME" }
        }
      }
    }
    ```

    Затем полностью закройте и снова запустите Claude Desktop — закрытия окна недостаточно,
    так как конфигурация MCP перечитывается только при полном перезапуске.

    **Custom Connectors** в веб-версии Claude.ai и встроенный интерфейс **Connectors** в Claude Desktop поддерживают
    только OAuth и не имеют поля для статического токена bearer, поэтому ни то,
    ни другое сегодня не работает с Agent Wiki.
  </Tab>
</Tabs>

## Что может делать агент {#what-the-agent-can-do}

После подключения агент получает такие инструменты:

| Инструмент | Что делает |
| --- | --- |
| `search_wiki` | Поиск по ключевым словам по страницам, которые вы можете читать |
| `ask_nl_question` | Задать вопрос обычным языком и получить ответ с источниками |
| `read_doc` | Прочитать страницу в текущей версии или в любом прошлом коммите |
| `list_history` | Журнал коммитов страницы |
| `search_comments` | Поиск по обсуждениям с глубокими ссылками |
| `write_doc` | Создать страницу или заменить её содержимое |
| `edit_doc` / `multi_edit` | Правки поиском и заменой, по одной или пакетом атомарно |
| `apply_patch` | Применить unified diff |
| `update_doc_nl` | Передать страницу собственному обновляющему агенту вики с инструкцией |
| `move_path` | Переименовать или переместить страницу или папку |
| `create_directory` | Создать папку |
| `delete_doc` | Переместить страницу в корзину с возможностью восстановления в течение 30 дней |
| `add_comment` / `reply_comment` / `resolve_comment` | Участвовать в обсуждениях |
| `list_templates` | Показать список стартовых шаблонов для новых страниц |
| `set_update_policy` | Задать, как вики может автоматически обновлять страницу или папку |

Правки — обычные коммиты git от вашего имени, поэтому всё, что делает агент, видно в истории страницы и обратимо.

## Права и безопасность {#permissions-and-safety}

- **Токен полностью наследует ваши права.** Ключ, созданный администратором, — ключ администратора. Создавайте ключи из
  аккаунта, доступ которого вы действительно хотите дать агенту.
- **Удаления обратимы.** `delete_doc` перемещает страницу в корзину с 30-дневным окном восстановления и работает только со страницами —
  удаление папок остаётся действием человека.
- **Ключи можно отозвать.** Отзывайте в **Agents & Actions** в любое время.

## Устранение неполадок {#troubleshooting}

<AccordionGroup>
  <Accordion title="missing required argument 'commandOrUrl'">
    URL оказался после `--header` в `claude mcp add`. Поставьте URL сразу после имени сервера, а `--header` — последним.
  </Accordion>

  <Accordion title="No MCP server found из другого каталога">
    Сервер был добавлен в локальной области. Добавьте его заново с `-s user`, чтобы он был доступен везде.
  </Accordion>

  <Accordion title="Соединение обрывается или не устанавливается при локальной разработке">
    Направьте клиент прямо на бэкенд (`http://localhost:8080/api/mcp`), а не на сервер разработки Next.js.
    Перезапись `/api/:path*` сервера разработки буферизует ответы и ломает транспорт, когда клиент отправляет `Accept:
    text/event-stream`.
  </Accordion>

  <Accordion title="Ссылки в результатах инструментов указывают на неверный хост">
    Результаты инструментов строят абсолютные URL из `PUBLIC_BASE_URL`. Если он неверен, то и ссылки неверны — см.
    [Конфигурация](/agent-wiki/deployment/configuration).
  </Accordion>
</AccordionGroup>
