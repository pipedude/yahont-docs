Helm-чарт устанавливает Agent Wiki — бэкенд, рабочие процессы, фронтенд,
постоянные тома и Ingress — в любой существующий кластер Kubernetes. Это поддерживаемый способ запуска в продакшене.

В репозитории также есть шаблон Terraform в `deploy/terraform/`, который создаёт небольшой кластер EKS,
если у вас его нет. Это отправная точка, которую нужно скопировать в собственный репозиторий и настроить,
а не поддерживаемая часть продукта.

## Требования {#requirements}

- `kubectl` и `helm` 3.13 или новее
- Зона DNS, в которой можно направить запись на балансировщик нагрузки ingress
- **Postgres 17**, доступный по `DATABASE_URL`
- Redis и OpenSearch, также доступные из кластера

Достаточно обычного Postgres — расширения и настройка `shared_preload_libraries` не нужны. Поиск работает на OpenSearch,
а очереди задач — на Redis, поэтому управляемый инстанс работает без изменений.

Чарт намеренно **не** создаёт Postgres, Redis или объектное хранилище. Используйте собственные — RDS, Cloud SQL,
самостоятельно управляемые, любые, с которыми вы уже работаете.

## Установка {#install}

<Steps>
  <Step title="Направьте DNS на ingress">
    Получите имя хоста балансировщика нагрузки у вашего ingress-контроллера:

    ```bash
    kubectl -n ingress-nginx get svc ingress-nginx-controller \
      -o jsonpath='{.status.loadBalancer.ingress[0].hostname}'
    ```

    Создайте CNAME для нужного хоста и дождитесь его разрешения. Если установлен cert-manager,
    сертификат Let's Encrypt выпускается по HTTP-01, как только DNS разрешается и чарт установлен.
  </Step>

  <Step title="Установите чарт">
    ```bash
    export DATABASE_URL='postgresql://…'   # your Postgres connection string

    helm upgrade --install agent-wiki ./deploy/helm/agent-workspace \
      --namespace agent-wiki --create-namespace \
      --set secretKey="$(openssl rand -hex 32)" \
      --set databaseUrl="$DATABASE_URL" \
      --set image.backend.tag=v0.0.1 \
      --set image.frontend.tag=v0.0.1 \
      --set ingress.host=<your-host> \
      --set ingress.clusterIssuer=letsencrypt-prod \
      --set ingress.tls.enabled=true
    ```

    Репозитории образов по умолчанию — `onyxdotapp/agent-wiki-{backend,frontend}`,
    поэтому переопределять нужно только тег.
    Для чего-либо сложнее пробы храните отдельный `values.yaml` для каждой среды и используйте `-f`.

    Передача строки подключения через переменную не оставляет пароль базы данных в истории оболочки и в списке процессов
    — аргументы `--set` видны любому, кто может выполнить `ps` на этом хосте.
  </Step>

  <Step title="Войдите и настройте">
    Откройте `https://<ingress.host>` и зарегистрируйтесь — первый аккаунт становится администратором.
    Затем задайте поставщика в **Admin → Language Models**.
  </Step>
</Steps>

<Note>
  **Закрепляйте теги образов.** По умолчанию в чарте используется `latest`, который меняется,
  только когда создаётся тег версии, и может сильно отставать от текущей сборки.
  Явно задайте `image.backend.tag` и `image.frontend.tag`.
</Note>

`PUBLIC_BASE_URL` выводится из `ingress.host` как `https://<host>`,
поэтому конечная точка MCP и ссылки в письмах разрешаются правильно без дополнительной настройки.

## Одна реплика — по замыслу {#single-replica-by-design}

Чарт закрепляет за бэкендом и рабочим процессом по одной реплике, со стратегией `Recreate` и правилом affinity подов,
которое планирует их вместе. Это определяют два ограничения:

- Том `wiki-data` — **ReadWriteOnce**, и оба пода используют его совместно — реплики конкурировали бы за рабочее дерево
  git.
- Планировщик периодических задач работает **внутри процесса**,
  поэтому вторая реплика дважды запускала бы запланированные задания.

Масштабируйте вертикально, а не горизонтально, пока это не изменится.

## Эксплуатация после запуска {#day-2-operations}

**Обновления.** Создайте новый тег версии,
затем выполните `helm upgrade --set image.backend.tag=<new> --set image.frontend.tag=<new>`.

**Резервные копии.** Включите с помощью `backup.enabled=true`.
CronJob выгружает `git bundle` репозитория вики *и* `pg_dump` базы данных вместе в любой S3-совместимый бакет.

<Warning>
  Нужны обе половины. Пакет git содержит содержимое страниц; права,
  комментарии и политики обновления хранятся только в Postgres.
  Восстановление только из одной из них оставит вики неработоспособной.
</Warning>

**Удаление.** `helm uninstall agent-wiki -n agent-wiki`. Для постоянных томов используется политика возврата `Retain`,
поэтому диски переживают удаление, и их нужно удалять вручную, если они вам больше не нужны.
