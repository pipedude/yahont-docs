Agent Wiki настраивается переменными окружения на уровне развёртывания и в консоли администратора — для всего,
что администратор должен менять без повторного развёртывания: поставщики моделей, Slack, почта, шаблоны.

Эта страница описывает сторону окружения.

## Обязательные {#required}

Обе проверяются при запуске. Если любая задана неверно, бэкенд отказывается запускаться,
а не работает в сломанном состоянии.

| Переменная | Примечания |
| --- | --- |
| `SECRET_KEY` | Подписывает сессии. Не должна быть пустой и не должна совпадать со встроенным значением для разработки |
| `PUBLIC_BASE_URL` | Источник, видимый браузеру, без завершающего слэша |

`PUBLIC_BASE_URL` намеренно никогда не выводится из заголовков запроса — подделанный `Host` иначе управлял бы URL,
которые выдаёт приложение. Он используется для построения конечной точки MCP,
глубоких ссылок лаунчера и ссылок в исходящих письмах, поэтому если он неверен, всё это неверно одинаковым образом.
В Kubernetes чарт берёт его из `ingress.host`.

## Хранилища данных {#data-stores}

| Переменная | По умолчанию |
| --- | --- |
| `DATABASE_URL` | `postgresql://postgres:postgres@postgres:5432/agent_wiki` |
| `REDIS_URL` | `redis://redis:6379/0` |
| `OPENSEARCH_URL` | `http://opensearch:9200` |
| `OPENSEARCH_INDEX` | `wiki-docs` |
| `WIKI_DIR` | Где находится рабочее дерево git |

Подойдёт обычный Postgres 17 — расширения и настройка параметров сервера не нужны. Поиск обслуживает OpenSearch,
а очереди задач — Redis, поэтому управляемые предложения баз данных работают без особой настройки.

## Аутентификация {#authentication}

| Переменная | Примечания |
| --- | --- |
| `AUTH_MODE` | `basic` (электронная почта и пароль, по умолчанию) или `oidc` |
| `OIDC_ISSUER` | URL издателя, когда `AUTH_MODE=oidc` |
| `OIDC_CLIENT_ID` | |
| `OIDC_CLIENT_SECRET` | |
| `OIDC_REDIRECT_URI` | |
| `ALLOWED_EMAILS` | Ограничивает, кто может зарегистрироваться |

При `basic` первый созданный аккаунт становится администратором — поэтому займите его сразу после установки,
а не оставляйте свежий инстанс доступным.

## Шифрование {#encryption}

`ENCRYPTION_KEY_SECRET` шифрует чувствительные столбцы в состоянии покоя — URL вебхуков Slack, токены MCP,
учётные данные поставщиков. Если он не задан, приложение использует `SECRET_KEY`,
что соответствует прежнему поведению и сохраняет расшифровываемость существующих данных.

Задайте его, когда нужно менять ключ шифрования независимо от ключа подписи cookie.
Он должен содержать не менее 32 символов, а для ротации есть отдельный скрипт — не просто меняйте значение,
иначе существующий шифртекст станет нечитаемым.

## Прочее {#other}

| Переменная | По умолчанию | Примечания |
| --- | --- | --- |
| `AGENT_WIKI_PORT` | `8090` | Порт хоста, публикуемый nginx в Compose |
| `MAX_QUEUE_SIZE` | `1000` | Предел очереди задач |
| `MCP_NL_DEBOUNCE_SECONDS` | `30` | Схлопывает повторные вызовы `update_doc_nl` для одной страницы. Увеличьте для контроля затрат |
| `DEV_MODE` | `false` | Только для локальной разработки — снижает проверку секретного ключа с фатальной до предупреждения. **Никогда не задавайте в продакшене** |

## Что меняется в консоли администратора {#changed-in-the-admin-console-instead}

Не ищите для них переменные окружения — это настройки времени выполнения,
которые администратор может менять без повторного развёртывания:

- **Поставщики моделей и ключи** — [Языковые модели](/agent-wiki/admin/language_models)
- **Учётные данные приложения Slack и исходящая почта** — [Уведомления](/agent-wiki/admin/notifications)
- **Конечная точка и ключ интеграции с Yahont** — [Интеграция с Yahont](/agent-wiki/admin/yahont_integration)
- **Поведение Auto Organize** — [Auto Organize](/agent-wiki/automate/auto_organize)
