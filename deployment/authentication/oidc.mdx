Настройте в Yahont аутентификацию OpenID Connect (OIDC). Доступна с распространёнными поставщиками удостоверений,
такими как Okta и Microsoft Entra ID (Azure AD).

Поставщики OIDC настраиваются в **Панель администратора** → **Организация** → [Поставщики
SSO](/deployment/authentication/sso_providers). Переменные окружения и перезапуски не нужны,
и можно настроить несколько поставщиков и включить их одновременно (см.
[Доступность в Yahont CE и Enterprise Edition](/deployment/authentication/sso_providers#plan-availability)).

В этом руководстве описана настройка для Okta. Другие поставщики удостоверений настраиваются похожим образом.
Свяжитесь с нами, если нужна помощь с другим поставщиком удостоверений.

## Руководство {#guide}

<Steps>
  <Step title="Создайте приложение Okta">
    Откройте Okta **Admin Console** → **Applications** → **Create App Integration**.

    <img className="rounded-image" src="/assets/deployment/oidc_create_integration.png" alt="Страница создания интеграции в Okta"/>
  </Step>

  <Step title="Настройте приложение Okta">
    Выберите **OIDC** и **Web Application**.

    Назовите приложение `Yahont`.

    <Tip>
      Если вы используете white labeling Yahont, приложение можно назвать как угодно.
    </Tip>

    Добавьте **Sign-in redirect URI** с именем, которое вы дадите поставщику в Yahont (slug в нижнем регистре,
    например `okta`):

      ```
      https://YOUR_YAHONT_DOMAIN.com/api/auth/oidc/YOUR_PROVIDER_NAME/callback
      ```

    Определите, должны ли все пользователи или выбранные группы иметь доступ к Yahont,
    либо пропустите этот шаг и назначьте пользователей позже.

    <img className="rounded-image" src="/assets/deployment/oidc_config.png" alt="Страница настройки приложения OIDC в Okta"/>
  </Step>

  <Step title="Сохраните учётные данные OIDC">
    Создайте новое приложение и сохраните **Client ID** и **Client Secret**.

    Также запишите **Okta Base URL** в формате `https://<YOUR_ORG_NAME>.okta.com`.

    <img className="rounded-image" src="/assets/deployment/oidc_secrets.png" alt="Страница учётных данных OIDC в Okta"/>

    <Note>
      После сохранения приложения можно загрузить логотип Yahont или свой логотип для white labeling,
      нажав значок шестерёнки рядом с названием приложения `Yahont`
    </Note>
  </Step>

  <Step title="Добавьте поставщика в Yahont">
    Откройте **Панель администратора** → **Организация** → [Провайдеры SSO](/deployment/authentication/sso_providers)
    и нажмите **Add Provider**.

    Выберите тип поставщика **OIDC**, введите **Name**, использованное в redirect URI, и вставьте **Client ID**,
    **Client Secret** и URL конфигурации OpenID:

      ```
      https://<YOUR_OKTA_BASE_URL>/.well-known/openid-configuration
      ```

    После создания поставщика в его строке показывается точный **Redirect URI**. Убедитесь,
    что он совпадает с зарегистрированным в Okta, затем войдите через новый вариант на странице входа.
  </Step>
</Steps>

## Настройка запрашиваемых областей {#customizing-requested-scopes}

По умолчанию Yahont использует базовые области OIDC по стандарту при перенаправлении пользователей к поставщику
удостоверений. Переопределять список имеет смысл в первую очередь тогда, когда токен доступа, выданный при входе,
должен передаваться в вызовы инструментов, которым нужны дополнительные области поставщика удостоверений.

Задайте **Scopes** в записи поставщика (**Панель администратора** → **Организация** → **Провайдеры SSO**),
чтобы переопределить список для каждого поставщика. **Scopes** поставщика имеют приоритет. Если поле пусто,
применяется переменная окружения всего развёртывания, затем встроенные значения по умолчанию.

Переменная окружения всего развёртывания `OIDC_SCOPE_OVERRIDE` задаёт список через запятую,
который применяется ко всем поставщикам OIDC:

```bash .env
OIDC_SCOPE_OVERRIDE=openid,email,profile,groups
```

Yahont всегда дополнительно запрашивает `offline_access`, чтобы выдавались токены обновления,
даже если его нет в списке переопределения.

<Warning>
  Переопределение **заменяет** области по умолчанию — убедитесь, что `openid`, `email` и `profile` по-прежнему включены,
  если хотите, чтобы стандартный вход продолжал работать.
</Warning>

<Note>
  Все добавляемые здесь области также должны быть включены для приложения у вашего поставщика удостоверений.
  Yahont меняет только то, что отправляется в запросе авторизации;
  поставщик удостоверений по-прежнему отклоняет области, не настроенные для клиента.
</Note>

## Включение PKCE {#enabling-pkce}

PKCE по умолчанию отключён для обратной совместимости с существующими развёртываниями OIDC.

Включите **Enable PKCE** в записи поставщика (**Панель администратора** → **Организация** → **Провайдеры SSO**).

Переменная окружения всего развёртывания `OIDC_PKCE_ENABLED` включает его для всех поставщиков:

```bash .env
OIDC_PKCE_ENABLED=true
```

<Warning>
  `OIDC_PKCE_ENABLED=true` принудительно включает PKCE для каждого поставщика, в том числе для тех,
  у кого переключатель **Enable PKCE** выключен. Отмените её, если хотите,
  чтобы источником истины были переключатели отдельных поставщиков.
</Warning>
