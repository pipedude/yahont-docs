## Обзор {#overview}

Объектное хранилище — это S3-совместимый сервис,
который Yahont с самостоятельным размещением поставляет для хранения файлов: вложений чата, загрузок,
вложений коннекторов, снимков Craft и других файлов, которые Yahont держит вне PostgreSQL.
Он запускает [SeaweedFS](https://github.com/seaweedfs/seaweedfs) одним процессом и заменяет встроенный MinIO.
Переход с MinIO выполняется автоматически. См.
[Миграция объектного хранилища](/admins/advanced_configs/object_store_migration).

Вместо него можно использовать AWS S3, Google Cloud Storage, Azure Blob Storage или любой S3-совместимый сервис.
Задайте `FILE_STORE_BACKEND` и соответствующие переменные из [справочника по
конфигурации](/deployment/configuration/configuration) и оставьте объектное хранилище выключенным.

## Docker Compose {#docker-compose}

Сервис `object-store` входит в профиль `s3-filestore` Compose, который `.env` включает по умолчанию.
Приложение обращается к нему по `S3_ENDPOINT_URL=http://object-store:8333` и аутентифицируется парой
`S3_AWS_ACCESS_KEY_ID` / `S3_AWS_SECRET_ACCESS_KEY`, которую хранилище использует как учётные данные администратора.
Установщик генерирует эту пару. Если вы пишете `.env` вручную,
перед запуском в работу смените значение по умолчанию `minioadmin`.

Данные лежат в томе `object_store_data`. Из контейнера наружу выходит только порт S3: порты filer,
master и volume SeaweedFS принимают запросы без учётных данных, поэтому внутри контейнера они слушают loopback.

## Использование собственного хранилища {#using-your-own-storage}

Чтобы работать без объектного хранилища, выключите его и укажите приложению ваше хранилище.

В Compose уберите `s3-filestore` из `COMPOSE_PROFILES` и задайте в `.env` те же переменные: `FILE_STORE_BACKEND=s3`,
`S3_FILE_STORE_BUCKET_NAME` и пару `S3_AWS_ACCESS_KEY_ID` / `S3_AWS_SECRET_ACCESS_KEY` для вашего хранилища.

## Размер {#sizing}

Хранилищу нужно столько места на диске, сколько занимают ваши файлы, плюс столько же во время миграции с MinIO,
пока оба хранилища содержат все файлы. Потребности в процессоре и памяти невелики:
копирование миллиона файлов заняло около двух ядер и менее 2 ГБ памяти, а в покое нужно намного меньше.
