На этой странице описаны процесс выпуска Yahont, схема версионирования и то,
как обновления доставляются в разные каналы развёртывания.

## Каналы выпуска {#release-channels}

<Note>
  Yahont поддерживает несколько каналов выпуска,
  чтобы предоставлять стабильные и разрабатываемые версии для разных сценариев.
</Note>

### GitHub {#github}

Наши [релизы на GitHub](https://github.com/onyx-dot-app/onyx/releases) публикуют образы в Docker Hub.
У Yahont два типа релизов:
- **Последняя стабильная версия** — релизы, готовые к использованию в продакшене
- **Предварительная версия** — бета-релизы для тестирования

Ветка `main` [репозитория Yahont](https://github.com/onyx-dot-app/onyx) — наша ветка разработки.

<Warning>
  Хотя мы стараемся сохранять `main` стабильной с помощью тестов CI/CD и ревью кода,
  мы не рекомендуем использовать `main` в продакшене.
</Warning>

### Docker Hub {#docker-hub}

[Docker Hub](https://hub.docker.com/r/onyxdotapp/onyx) хранит сами образы контейнеров.
Новые образы публикуются каждую ночь из ветки `main` и при выпуске нового релиза.

Чтобы определить последние образы программно, используйте нашу конечную точку API:

```
https://cloud.yahont.ai/api/versions
```

Эта конечная точка возвращает текущие последние стабильную и бета-версии, доступные в Docker Hub.

<Tip>
  Если при развёртывании Yahont вы не указываете версию, вы получите последние ночные сборки.
</Tip>

## Схема версионирования {#versioning-scheme}

Yahont следует [семантическому версионированию (SemVer)](https://semver.org/) с понятным, предсказуемым форматом.

**Формат стандартной версии:**

```
major.minor.hotfix
```

**Формат предварительной версии:**

```
major.minor.hotfix-beta.betahotfix
```

**Примеры:**
- Стабильный релиз: `1.2.3`
- Предварительный релиз: `1.3.0-beta.1`
- Hotfix беты: `1.3.0-beta.2`

<Note>
  - **Major-версия** — увеличивается при несовместимых изменениях
  - **Minor-версия** — увеличивается при новых функциях, исправлениях ошибок и обратно совместимых изменениях
  - **Hotfix-версия** — увеличивается только при бэкпорте исправлений ошибок в релизы
</Note>

### Файлы Docker и Helm-чарты {#docker-files-and-helm-charts}

Изменения в файлах Docker и Helm-чартах увеличивают номера версий в соответствующих файлах.

## График выпусков {#release-schedule}

Yahont следует предсказуемому еженедельному циклу выпусков.

**Каждый понедельник:**
- Последняя предварительная версия переводится в стабильную
- `main` замораживается как новая предварительная версия

### Процесс hotfix {#hotfix-process}

- Критические исправления ошибок **бэкпортируются** в стабильные релизы по необходимости
- Hotfix-релизы обходят обычный еженедельный цикл при срочных проблемах в продакшене
- Исправления получают и стабильная, и предварительная ветки, когда это применимо

## Рекомендации по обновлению {#update-best-practices}

Чтобы поддерживать стабильное развёртывание, мы рекомендуем оставаться на последнем стабильном релизе.
Он помечен номером версии вида `v1.2.3`.

<Steps>
  <Step title="Проверьте тег стабильной версии через API версий">
    Сравните вашу текущую версию с тегом последнего стабильного релиза.
    Конечная точка версий публичная и не требует аутентификации.

    ```bash
    curl -X GET "https://cloud.yahont.ai/api/versions"
    ```

    Найдите в ответе ключ `stable: onyx`.

    ```json Example Response expandable
    {
      "stable":{
        "onyx":"v1.8.1",
        "relational_db":"postgres:15.2-alpine",
        "index":"vespaengine/vespa:8.277.17",
        "nginx":"nginx:1.23.4-alpine"},
        "dev":{
          "onyx":"v1.9.0-beta.0",
          "relational_db":"postgres:15.2-alpine",
          "index":"vespaengine/vespa:8.277.17",
          "nginx":"nginx:1.23.4-alpine"
        },
        "migration":{
          "onyx":"airgapped-intfloat-nomic-migration",
          "relational_db":"postgres:15.2-alpine",
          "index":"vespaengine/vespa:8.277.17",
          "nginx":"nginx:1.23.4-alpine"
        }
      }
    }
    ```
  </Step>

  <Step title="Запустите Yahont с тегом версии">
    Способ запуска конкретной версии Yahont зависит от вашего процесса развёртывания.

    <Note>
      Не забудьте префикс `v`! То есть `v1.2.3` — правильно, `1.2.3` — неправильно.
    </Note>

    <AccordionGroup>
      <Accordion title="Загрузка образов Docker">
        Укажите тег версии в окружении.

        ```bash
        IMAGE_TAG=<v.MAJOR.MINOR.HOTFIX> docker compose -f docker-compose.dev.yml -p onyx-stack up -d --pull always --force-recreate
        ```
      </Accordion>
    </AccordionGroup>

    <Accordion title="Сборка образов Docker">
      Загрузите ветку релиза с GitHub или только помеченную версию и соберите образы.

      Ветка релиза — место, где публикуется последняя стабильная версия.
      Ветки релизов называются `release/v<MAJOR>.<MINOR>`.

      В репозитории Yahont:

      ```bash From Release Branch
      git fetch origin release/v1.2
      git switch release/v1.2

      docker compose -f docker-compose.dev.yml -p onyx-stack up -d --build --force-recreate
      ```

      ```bash From Tagged Version
      git fetch origin tag v1.2.3
      git switch --detach v1.2.3

      docker compose -f docker-compose.dev.yml -p onyx-stack up -d --build --force-recreate
      ```
    </Accordion>

    <Accordion title="Helm">
      Чтобы указать версию при развёртывании с Helm, задайте значение `global: version` в файле `values.yaml`.

      ```yaml values.yaml
      global:
        version: "v1.2.3"
      ```
    </Accordion>
  </Step>
</Steps>
